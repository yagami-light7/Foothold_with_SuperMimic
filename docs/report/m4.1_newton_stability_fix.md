# M4.1 v2 Roban Newton 稳定性修复

## 定位

在 RTX 4060 Laptop GPU 上，原配置接受限位内的目标，仍会在全幅固定随机序列中出现有限数值发散。128 个环境中，最大关节越界 2.012 rad、峰值关节速度 614.3 rad/s、根部线速度 41.05 m/s。关掉全部碰撞后，同种子仍复现更严重的发散，峰值关节速度达 15,348 rad/s，根部角速度达 3,647 rad/s。两组的 `overflow` 始终为零，末子步最大 `nefc` 分别为 120 和 16，远低于容量 1024。历史训练仅保存了第 1000 轮，无法还原两条原始异常的完整状态和接触缓存。固定序列已复现同类失效。

无接触复现的 `leg_l3_joint` 在第 3 个控制步收到 `0.747 rad` 的目标，上限为 `1.745 rad`。四个 5 ms 子步的 `q` 依次为 2.557、2.719、2.814、2.855 rad，`qd` 从 47.98 降至 8.27 rad/s。实测执行器力矩连续四个子步为 −70 N·m，限位约束力矩为 −126.3 至 −115.7 N·m，活动约束数为 2、3、3、3。软限位已介入，关节仍带着入射速度继续越界。完整排序和端点检查均通过。这个样本说明软限位穿透、低阻尼和大目标跃变足以触发异常。接触会改变轨迹和冲击，容量不足无法解释这两份历史日志。

## 修复与物理对照

保留 `configs/roban/m4_1.json` 作为基线。独立配置 `configs/roban/m4_1_v2.json` 使用 8 个 2.5 ms 子步，仍每 20 ms 下发控制命令。通过 USD 会话层将 21 个关节的限位 `solref` 时间常数从 20 ms 调至 8 ms，高于两个新子步。保留 `implicitfast`、150 次求解、`njmax=1024` 及每环境分配 `nconmax=256`。关节范围、Kp、力矩限幅、接触几何和 F2 参考沿用原设置。 [MuJoCo 约束参数](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)

阻尼由固定胸部质量矩阵的等效惯量 `J=1/diag(M⁻¹)` 估计。取中立姿态及 F2 每 20 帧的中位数，同组左右取平均，按 `Kd≈2·0.65·sqrt(Kp·J)−0.2` 设定需要增阻尼的关节。模型臂惯量为 `0.003 kg·m²`，已有的 `0.2 N·m·s/rad` 被动阻尼计入估算，静摩擦力矩为零。腰、髋和肩使用不同的 Kd，踝和远端手臂保留原值。奖励力矩代理读取同一 Kd。F2 的参考峰值关节速度为 5.38 rad/s。

D 中只加倍子步，故障环境从 124 降至 110。加速限位后降至 7。只调整 Kd 时为 28。组合配置消除了这组的关节和根部异常，另观察到 1 次 EPA 边缓冲告警，发生在全幅随机动作的第 80 步。该告警来自碰撞窄相，单独记录。组合配置关闭接触后，关节与根部异常从 127 降至 0，关节速度峰值从 15,348 降至 121.1 rad/s。基线第 1000 轮 Actor 的 logits 均值约 `6.9e−5`，标准差 `4.8e−4`，绝对峰值 `0.00231`，加 0.1 标准差噪声后没有 `|a|≥0.95`，该检查点未出现动作贴边。

组合配置在 128 环境的全幅对照中，末子步最大接触数和活动约束数为 32 和 93，最大求解迭代数为 8。基线对应为 32、120 和 9。组合配置的有接触全幅对照为 21.5k 控制步环境样本/s，基线为 36.9k/s，均排除初始化。单环境 80 步全幅对照未触发保护，峰值穿透 0.414 rad、关节速度 113.8 rad/s。128 环境按训练的跌倒条件停止累计指标时，未见告警或越界保护，峰值为 0.405 rad 和 114.9 rad/s。

## 训练验证

256 环境先完成 200 轮烟测，前 100 轮仅更新 WM。160,768 条有效转移中没有触发保护。随后以原 M4.1 超参数完成 1500 轮验证，共 992,768 条仿真转移，其中 992,751 条有效。第 1200 轮时累计有效转移已达到 800,768，越过历史失效规模。全程没有停机级发散、NaN/Inf 或约束容量告警。17 条关节越界转移被丢弃。检查点的 WM 单步根部位移各分量 RMS 最大为 1.64 cm，归一化样本数与有效转移数一致。

第 1203 轮首例越界从实际快照回放成功。该控制步中 `leg_r3_joint` 在 −94.2 rad/s 的入射速度下从 −0.358 rad 积分至 −2.523 rad，目标为 −1.576 rad。第 6 子步穿过下限，约束在第 7、8 子步反推约 394、347 N·m，执行器同时提交 +70 N·m。左腿 `leg_l2_link` 和 `leg_l4_link` 代理发生自碰撞，单个子步峰值法向冲量约 7.98 N·s，末子步 `nefc=7`、无溢出。相同八步回放中，基线的峰值关节速度为 226.7 rad/s，修复后为 94.2 rad/s（控制步采样），最大穿透则从 0.609 增至 0.778 rad。该样本保留为回归证据。

Actor 更新期间最大关节穿透 0.94 rad、峰值关节速度约 188 rad/s、根部线速度和角速度峰值 5.18 m/s 与 46.9 rad/s。第 1500 轮的日志窗口内 `|a|≥0.95` 占 48.0%，末子步力矩饱和占 38.6%。Actor 输入仍为 `10×69` 本体历史与 320 维足部/根部目标，Critic 总输入仍为 970 维。

独立 Newton 评估使用种子 1001、1002。第 1500 轮策略在两次评估中均存活 0.72 s，两次都观测到第一次摆脚，均未匹配首次落脚。相对同配置 `initial.pt`，Root RMSE 从 0.282 m 降至 0.170 m，Foot RMSE 从 0.360 m 升至 0.594 m，接触一致率从 59.7% 降至 20.8%。完整 F2 步态学习仍未达标。

同配置从第 1500 轮恢复到 1502 轮，验证时将 `recovery_wm_iters` 设为 0，补填 Replay 后直接更新 Actor/Critic。基线检查点在恢复入口返回 `Resume physics contract mismatch`。32 项现有 CPU 测试通过，另验证了诊断快照的分级覆盖。

## 诊断与运行入口

- `supermimic/integration/m4_task.py` 验证并配置子步、关节限位和 Kd，在检查点记录实际物理配置。`supermimic/env.py` 复用真实的目标提交和积分路径。
- `supermimic/integration/m4_dynamics.py` 和 `tools/run_roban.sh` 提供固定动作、无接触、固定胸部和子步追踪，可读回子步法向力及碰撞对。`supermimic/roban_runtime.py` 提供物理配置参数。
- `supermimic/train.py` 与 `supermimic/networks.py` 在开启诊断时读取既有 Actor 的 logits。训练每次日志输出限位、速度、饱和、约束和异常计数。故障时最多保留一个 `dynamics_fault.npz`，包含最近八步的状态、动作、PD 目标、理论与实测力矩、加速度、接触数、求解迭代、F2 帧、环境和种子。触发停机的快照可以覆盖轻度异常快照。

从仓库根目录复现对照。以下临时目录仅用于复用同一 Actor 动作和观察首次故障。

```bash
case_dir=$(mktemp -d outputs/m4_1/.dynamics.XXXXXX)
bash tools/run_roban.sh m4-dynamics --roban_config configs/roban/m4_1.json \
  --num_envs 128 --steps 80 --actor_checkpoint outputs/m4_1/checkpoints/early.pt \
  --save_actions "$case_dir/actions.npz"
bash tools/run_roban.sh m4-dynamics --roban_config configs/roban/m4_1_v2.json \
  --num_envs 128 --steps 80 --replay_actions "$case_dir/actions.npz"
bash tools/run_roban.sh m4-dynamics --roban_config configs/roban/m4_1.json \
  --num_envs 128 --steps 80 --cases full --no_contacts \
  --trace "$case_dir/air_fault.npz" --trace_substeps
bash tools/run_roban.sh m4-dynamics --roban_config configs/roban/m4_1_v2.json \
  --pd_steps --steps 60
```

1500 轮验证保存在 `outputs/m4_1/v2_validation`，含检查点、训练表和一份真实故障快照。可用 `m4-dynamics --replay_fault outputs/m4_1/v2_validation/dynamics_fault.npz` 重放，同一命令加 `--trace` 和 `--trace_substeps` 可导出子步信息。

新物理配置应建立独立运行。下面第二条命令从已验证的第 1500 轮续训，目标轮次取配置中的 5000。第三条命令可直接评估已保存的验证运行。

```bash
bash tools/run_roban.sh m4-train \
  --roban_config configs/roban/m4_1_v2.json \
  --log_dir outputs/m4_1/v2/checkpoints --fresh_start

bash tools/run_roban.sh m4-train \
  --roban_config configs/roban/m4_1_v2.json \
  --log_dir outputs/m4_1/v2_validation/checkpoints \
  --resume outputs/m4_1/v2_validation/checkpoints/last.pt

bash tools/run_roban.sh m4-evaluate \
  --out outputs/m4_1/v2_validation --seeds 1001 1002 --no_video
```
