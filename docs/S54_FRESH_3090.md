# S54 从零训练：WM 1000 iterations，大并行 3090 配置

当前用户选择覆盖旧的权重迁移/恢复方案：新建实验，从零初始化 WM、Actor、Critic、优化器、normalization、Replay、课程及计时。原日志/checkpoint保留。2026-11-04稳定性审查后，已按用户条件授权启动 `s54_curriculum_fresh_auditfix_20261104_032902`，修复、短测和管理命令见 [S54_TRAINING_AUDIT.md](S54_TRAINING_AUDIT.md)。已有实验运行时不要重复启动。

直接运行：

```bash
bash tools/train/run_s54_curriculum_8h.sh fresh
```

实际配置位于 `configs/s54/curriculum/s54_curriculum_fresh_3090.json`，启动时复制为新目录的 `train_profile.json`；最终生效参数仍以 `args.json` 为准。fresh 模式强制 `--fresh_start`，禁止同时指定 `--resume` 或 `--init_weights`。

前1000次 iteration只更新WM，不更新Actor/Critic网络参数；采样期间观测/Goal的normalization正常更新。从日志iteration1001开始Actor/Critic更新。WM-only不是1000个环境步，也不是BPTT Horizon。UTD=.4时每iteration交替采2/3个向量控制步，4096环境平均每轮获得10240个真实transitions。

WM warmup1000结束保存独立完整 `wm_calibrated.pt`，另有周期/latest/真实Newton评估best，文件名不代表已通过WM准确性或站立验收。保留此前动作契约一致性和foot bootstrap合法上界修复。学习率、物理终止条件、奖励和成功率不会为满足显存目标而放宽。

新实验预算从0计，最多8h，含初始化、1000 WM预热、评估和保存；不是在8h之外额外增加1000 WM iterations。延长WM校准不能保证Actor后续不失稳，仍需看独立Newton表现和raw Critic/target监控。

## 串行容量短测

每组16 iterations，**仅容量测试显式把WM-only缩为4**，以覆盖后续Actor反传显存；生产profile始终1000。各组都从零初始化，没有载入旧权重。短测不是收敛评估。

| Envs | Replay steps | WM batch | Actor batch | device取样峰值 MiB | Actor阶段 it/s | 真实transitions/s |
|---:|---:|---:|---:|---:|---:|---:|
| 1024 | 2048 | 1024 | 256 | 3814 | 1.796 | 4598 |
| 2048 | 4096 | 2048 | 512 | 10444 | 1.795 | 9191 |
| 2048 | 4096 | 4096 | 1024 | 11504 | 1.573 | 8053 |
| **4096** | **3072** | **4096** | **1024** | **15904** | **1.503** | **15386** |

最终设备占用约15.5GiB、Torch峰值allocated约13.6GiB，无OOM，明显高于原512环境约1.6GiB；真实采样吞吐约为原短测2.7k/s的5.6倍。GPU利用率取样含启动/保存，不能据此声称算力已充分利用。

其中Replay tensor本身约11.2GiB；扩大Replay是为了保留更多校准与近期混合数据，显存增长不全来自计算并行。3072时间容量可覆盖fresh warmup256步+WM1000 iterations约2500步，不需要用更长Horizon来占显存。每环境3072步=61.44s仿真时间，实际buffer覆盖的wall time随吞吐而变。

完整Replay command_store和后续更复杂任务的长期额外占用尚未跑满验证。目标保留数GiB余量，fresh及其resume启动前要求至少21500MiB空闲、无已有compute任务；运行时每20iterations检查设备总占用，达到21500MiB时请求安全保存退出。这个阈值是训练资源保护，不是物理终止或成功率修改。若发生外部任务突然抢占，仍不能绝对保证不OOM。

证据：`results/s54/fresh_capacity.json`、`fresh_capacity_large.json`；重跑工具 `tools/benchmarks/benchmark_s54_fresh.py` 及 `--large`。

## tmux、SwanLab及恢复

默认运行名 `s54_curriculum_fresh_YYYYMMDD_HHMMSS`，时间戳为北京时间；SwanLab仍在 `Foothold_with_SuperMimic`，新建独立时间戳实验。训练与上传均由tmux管理，SSH退出不影响运行。日志持久化，旧实验不覆盖。

```bash
# 启动后将RUN替换为打印的实际名字
RUN=s54_curriculum_fresh_YYYYMMDD_HHMMSS
bash tools/train/run_s54_curriculum_8h.sh status "$RUN"
tail -n 20 -F "logs/$RUN/stdout.log"
tmux attach -t "$RUN"  # Ctrl-b 然后d离开
bash tools/train/run_s54_curriculum_8h.sh stop "$RUN"
# 只在安全退出后恢复；会读取该run保存的profile和实际args，继承已用预算
bash tools/train/run_s54_curriculum_8h.sh resume "$RUN"
```

profile恢复不会再次设置fresh_start；它恢复这次fresh实验的完整checkpoint，而不是重新随机初始化。

回归覆盖：fresh禁止旧权重、profile参数传递、resume实际覆盖参数、WM999/1000边界、状态日志非日志分支及显存保护、共享动作与bootstrap约束。未进行正式1000-WM+8h收敛验证。
