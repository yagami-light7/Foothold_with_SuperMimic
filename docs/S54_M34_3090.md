# 在 3090 服务器运行 M3.4 / M4

训练入口是 `tools/run_s54_m34.sh`，训练参数读取传入的 JSON。
`configs/s54_m34_4060.json` 的文件名不限定显卡；当前用户设置的 2048
环境、10000 iterations、每 1000 iterations 评估会原样生效。这组大配置
尚未在目标 3090 服务器实测，不代表已完成容量或收敛验证。

## 1. 同步代码和数据

先将最新脚本修改提交、推送，再在服务器拉取。
`data/` 被 Git 忽略，必须另行传输以下三个完整目录：

```text
data/s54_flat_dataset/dataset_export/
data/s54_description/
data/s54_newton_usd/
```

第一个目录包含 manifest、metadata、train/test 和配对原始数据；第二个包含
MJCF、URDF 与 meshes；第三个包含已验证的 29 关节 USD、contract、payloads
及材质文件。模型和数据哈希会在 CPU/真实 Newton gate 中重新检查。

可在本地仓库打包，再用自己的 scp/rsync 通道传到服务器：

```bash
tar -czf /tmp/s54_m34_assets.tar.gz \
  data/s54_flat_dataset/dataset_export \
  data/s54_description \
  data/s54_newton_usd
```

服务器进入仓库根目录后解压（将路径替换成上传文件的位置）：

```bash
tar -xzf /path/to/s54_m34_assets.tar.gz
```

## 2. 准备 Docker 环境

服务器需要可用的 NVIDIA 驱动、Docker GPU 支持，以及与当前实现匹配的
`supermimic:latest` 镜像。当前构建入口固定 Isaac Lab 源码版本及 Newton/MJWarp
环境，包含容器内 tmux、ffmpeg 和编译工具：

```bash
docker image inspect supermimic:latest
```

若尚无此镜像，可运行仓库现有构建入口，或从本机导入已验证的镜像：

```bash
bash tools/setup.sh
```

检查容器能看到 GPU：

```bash
docker run --rm --gpus all supermimic:latest nvidia-smi
```

启动器默认创建 `supermimic_s54_m34`，使用 GPU 0，挂载当前服务器仓库。
已有同名容器会检查挂载路径，不会删除它或切换到另一个仓库。新建容器的
`16g` 是宿主 RAM 上限，不是 GPU 显存上限。首次启动可能下载场景资产并编译
Warp/CUDA kernels；仿真和视频渲染需要镜像的 NVIDIA EGL 支持。

## 3. 在宿主机配置 SwanLab

M3.4 的设置在 `tools/run_s54_m34.sh` 顶部；`run_train.sh` 的设置属于旧入口。
SDK 在 Docker 宿主机运行，使用 Python 3.10+，不修改 Isaac Lab 容器中的依赖。
在服务器上以运行启动器的同一用户安装、登录：

```bash
python3 -m venv .venv-swanlab
.venv-swanlab/bin/python -m pip install -U swanlab
.venv-swanlab/bin/swanlab login
.venv-swanlab/bin/python tools/sync_swanlab.py --check --mode online
```

登录交互中输入自己的 API Key，不将 Key 写进配置或提交 Git。
安装和登录步骤见 [SwanLab 官方文档](https://docs.swanlab.cn/guide_cloud/general/quick-start.html)。

可直接编辑启动脚本顶部默认值，也可通过以下环境变量设置：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `SWANLAB_ENABLED` | `false` | `true` 时检查登录并自动启动上传 |
| `SWANLAB_PROJECT` | `SuperMimic` | 项目名 |
| `SWANLAB_WORKSPACE` | 空 | 空为默认个人空间；团队项目填写团队空间名 |
| `SWANLAB_EXPERIMENT` | 空 | 空时使用本次训练 RUN 名 |
| `SWANLAB_MODE` | `online` | `online` 或 `offline` |
| `SWANLAB_POLL_SECONDS` | `5` | 读取本地 CSV 的间隔 |
| `SWANLAB_STARTUP_TIMEOUT` | `3600` | 等待预检/PD/smoke 后正式 args.json 的上限 |
| `SWANLAB_PYTHON` | `.venv-swanlab/bin/python` | 宿主机 SDK Python 路径 |

上传固定使用 `--core_only`：核心超参数和 Loss、Reward、Episode、梯度与
吞吐指标；SDK 的硬件、运行环境、依赖列表、Git 和动态监控探针关闭。
逐动作诊断、完整配置、checkpoint 和 MP4 保留在本地。
上传器用独立的宿主进程会话跟随日志，训练用容器 tmux，均可跨 SSH 断开继续运行。

## 4. 启动

在服务器仓库根目录运行：

```bash
SWANLAB_ENABLED=true \
SWANLAB_PROJECT=SuperMimic-S54 \
bash tools/run_s54_m34.sh train s54_m34_3090_run01 configs/s54_m34_4060.json
```

团队项目可额外设置 `SWANLAB_WORKSPACE=你的团队空间名`。每次使用新的 RUN 名，
已有实验不会覆盖。未配置 SwanLab 时可按原命令运行，默认只记录本地日志：

```bash
bash tools/run_s54_m34.sh train s54_m34_3090_run01 configs/s54_m34_4060.json
```

查看训练和上传进度：

```bash
tail -f logs/s54_m34_3090_run01/stdout.log
tail -f logs/s54_m34_3090_run01/swanlab_sync.log
```

启动顺序：CPU 契约检查 → Newton PD/FK → 配对 Raw 诊断 → 30 次 smoke →
正式训练；每 1000 iterations 暂停训练，由独立 Newton 进程评估固定 checkpoint
的 train/test，然后继续原 replay/优化器。评估耗时计入 `wall_seconds`。
最终同一 checkpoint 已完成的评估会复用，结束后才批量渲染视频。

`pipeline_config.json`、`args.json` 是实际生效配置，周期评估保存在
`logs/RUN/evals/iter_001000/` 等目录。原实现入口和历史 checkpoint 保留。
