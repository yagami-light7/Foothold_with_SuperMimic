# M4.2 — Newton EPA_HORIZON 修复与 Action Scale 消融实验

## 任务背景

当前项目为 Roban 21 DoF 人形机器人，采用 SuperMimic 的 WM + BPTT + Asymmetric Actor–Critic，在 Isaac Lab 3.0 + Newton/MJWarp 中训练 F2 Footstep Tracking Policy。

M4.2 已经完成 Action Mapping 重构：

\[
q*{\mathrm{target}}=
\operatorname{clamp}(q_0+\alpha a,\ q*{\min},q\_{\max})
\]

其中：

- Actor：21 维 Linear 输出，不使用最终 `tanh`。
- \(q_0\)：经过站立验证的固定 Roban 默认站姿。
- 当前 Action Scale：\(\alpha=0.35\tau\_{\max}/K_p\)。
- PD Target 使用硬 `clamp`。
- Newton 使用 M4.1 v2 稳定性配置：8×2.5 ms 子步、8 ms 关节限位时间常数、逐关节阻尼修复。
- Actor：10×69 本体历史 + 320 维未来 Foot/Root Goals。
- Critic：970 维输入。

相关文件：

- `configs/roban/m4_2.json`
- `outputs/m4_2/checkpoints/`
- `outputs/m4_2/dynamics_fault.npz`
- `m4.2_report.md`
- `supermimic/integration/m4_task.py`
- `supermimic/integration/m4_dynamics.py`
- `supermimic/roban_runtime.py`
- `supermimic/train.py`

请先核实实际文件路径，不要假设所有文件都位于根目录。

## 一、当前故障

正式训练运行至约 1946 iterations、累计 2,556,928 条真实仿真转移后中断。

异常：

```text
Warning: EPA horizon = 24 isn't large enough.

FloatingPointError:
M4 Newton 异常，共 1 个环境，已拦截本批转移。

env=196
F2帧=159
Δp=0.04379m
|v|=2.088m/s
|ω|=6.376rad/s
|qd|max=51.47rad/s
状态有限=True
overflow=EPA_HORIZON
nefc(末子步)=14/1024
```

同时观察到：

| 训练阶段  | 原始动作最大值 | Target Clamp Ratio |
| --------- | -------------: | -----------------: |
| Iter 500  |          0.003 |                 0% |
| Iter 1000 |        0.00294 |                 0% |
| Iter 1500 |           55.2 |              6.40% |
| 中断前    |           41.4 |             10.84% |

WM Loss 在 Actor 开始更新后出现明显上升。

**注意：本次异常状态仍为有限值，不能直接认定发生了 Newton 数值发散。**

## 二、任务一：定位并修复 EPA_HORIZON

### 1. 复现异常

优先读取：

`outputs/m4_2/dynamics_fault.npz`

检查其中保存的完整状态、动作、碰撞信息、求解器状态与环境编号。

尝试在隔离环境中重放触发异常的状态。

如果快照不足以精确复现，请明确指出缺失信息，并增强快照机制，保存：

- 发生异常前后的机器人状态。
- 当前原始 Action、PD Target、实际关节速度。
- 当前接触几何体对。
- 相关接触点、法线、穿透深度。
- 关节位置及限位偏差。
- Newton/MJWarp 求解器告警与 Overflow 位。
- 完整的随机种子和复现配置。

尽可能识别具体引起 EPA 失败的几何体对。

重点排查足部与地面、腿部自碰撞，以及深度穿透导致的复杂凸体接触。

### 2. 判断 EPA_HORIZON 的严重程度

区分：

A. EPA 缓冲区告警，但实际状态与接触求解仍可信。

B. EPA 计算失败，导致某些接触不可靠，但尚未发生状态发散。

C. EPA 失败进一步引起非物理冲量、关节越界或数值发散。

分别判断：

- 是否会产生错误的接触力。
- 是否影响 Reward 和 Termination。
- 是否污染 Replay Buffer。
- 是否影响 World Model 训练。
- 是否可以仅重置受影响环境。

### 3. 设计最小修复

按优先级考虑：

1. 修复可能导致深度穿透的碰撞几何体或自碰撞配置。
2. 检查 Newton/MJWarp 对 EPA Horizon 容量的配置及实现，确认是否能够安全调整。
3. 检查异常前物理子步和接触状态是否异常。
4. 如果 EPA 告警无法完全避免，设计按环境隔离的异常恢复机制。

原则：

- **不允许直接关闭全部 Overflow 检查。**
- 不允许仅通过 `warn_overflow=0` 隐藏告警。
- 不允许未经验证就增大 `njmax`，因为 EPA Horizon 和 `nefc` 不是同一容量。
- 不允许直接忽略告警后将可疑转移写入 Replay。
- 不允许影响其他正常环境的采样与训练。

如果能够确认某个环境发生不可靠碰撞，应将该环境的异常转移标记为无效，安全重置，并保证 Replay 的状态、动作、next_state、termination 以及序列边界保持一致。

如果当前接口不能安全实现单环境恢复，请明确说明限制，不要采用不完整的恢复逻辑。

保留 NaN/Inf、严重速度异常、关节越界、碰撞异常等必要保护。

## 三、任务二：检查 Action Scale 0.35 是否过大

当前：

\[
\alpha*j=0.35\frac{\tau*{\max,j}}{K\_{p,j}}
\]

官方 SuperMimic 配套 G1 参考：

\[
\alpha*j=0.25\frac{\tau*{\max,j}}{K\_{p,j}}
\]

请比较两个配置，并结合当前 Roban 真实训练数据判断是否需要回退到 0.25。

### 1. 分析训练中的动作分布

读取现有 M4.2 日志及 Checkpoint，重点比较 Iter 1000、1500、最后有效 Checkpoint。

检查：

- Actor Action Mean / Std / P95 / P99 / Max。
- 各关节动作分布。
- 每关节 Target Clamp Ratio。
- 动作变化率。
- PD Target 与实际关节位置误差。
- 实际执行器力矩饱和比例。
- Actor Gradient Norm。
- WM Loss 与真实 Rollout 误差。
- Imagined Reward 与真实 Reward 的偏差。

特别关注为什么 Actor 在 Iter 1000 后出现极大动作输出。

检查是否存在 World Model Exploitation、极端动作分布外推、梯度异常或动作正则不足。

不能仅根据最大 Action 数值判断 Scale 是否合理。

### 2. 进行 0.25 与 0.35 对照

构建两个配置：

- A：Action Scale = 0.35。
- B：Action Scale = 0.25。

其余条件完全保持一致，包括：

- \(q_0\)。
- PD 参数。
- Newton 求解器。
- 关节限位。
- F2 Reference。
- 奖励函数。
- 训练网络和超参数。

首先不做完整训练，使用相同状态和相同**原始动作**进行短时 Newton 测试，比较：

- PD Target 变化。
- Target Clamp Ratio。
- 关节速度和实际力矩。
- EPA_HORIZON 发生率。
- 非法状态数量。
- 短时存活率。

注意区分两种对照目的：

1. 固定相同原始 Action：比较两个 Scale 的控制灵敏度。
2. 固定相同物理 PD Target：检验同一物理目标下是否存在与 Scale 无关的数值问题。

如果需要进行短训练消融，请使用相同种子、初始化、环境数和采样预算，单独输出报告。

**不要直接用 0.35 的旧 Checkpoint 将 Scale 改为 0.25 后继续训练，并把结果视为公平消融。**

因为这样会改变现有 Actor 输出的物理含义，也会改变 World Model 的动作输入分布。

### 3. 验证 F2 动作表达能力

重新计算：

\[
a*{\mathrm{ref}}=
\frac{q*{\mathrm{F2}}-q_0}{\alpha}
\]

分别报告 0.25 和 0.35 时：

- 最大绝对动作。
- P95 / P99。
- 各关节 RMS。
- 相邻时刻动作变化。
- 机械限位裁剪比例。

由于 Actor 使用 Linear 输出，不允许简单地认为 `|a|>1` 就无法表达 F2。

重点考虑较小 Scale 是否会迫使 Actor 输出更大的归一化动作，从而增加 World Model 的分布外风险。

## 四、任务三：检查 BPTT 与 Clamp 的关系

当前 M4.2 的 World Model 使用裁剪后等效动作：

\[
a*{\mathrm{eff}}=
\frac{q*{\mathrm{target}}-q_0}{\alpha}
\]

请重点检查：

1. Newton 与 BPTT 的 PD Target 是否完全一致。
2. Replay 中保存的是原始 Action 还是有效 Action。
3. World Model 是否能正确表示裁剪区域的动力学。
4. 是否存在多个不同原始 Action 映射到同一 PD Target、但 Reward 或历史观测不同的问题。
5. 大量 Clamp 是否使 BPTT 的部分梯度失效。
6. `foot_grad=0` 的统计含义及原因。

如果认为需要增加 Action Regularization 或超限目标的软惩罚，请先提供定量证据。

可以评估：

\[
\mathcal L*{\mathrm{overflow}}=
\lambda\left\|
q*{\mathrm{raw}}-
\operatorname{clamp}
(q*{\mathrm{raw}},q*{\min},q\_{\max})
\right\|^2
\]

但不要未经对照就直接加入新的 Reward。

## 五、测试与训练恢复

修复完成后，执行以下测试：

**A. 异常快照回放**

验证原故障是否可复现，以及修复后是否消除或能够安全恢复。

**B. Newton 稳定性回归**

分别测试零动作、小幅随机动作、F2 参考动作及真实 Actor 输出，重点检查接触复杂场景。

**C. WM/BPTT 一致性**

验证动作变换一致、梯度有限、Replay 无异常跨越，并检查是否有梯度失效。

**D. 短训练验证**

以最小必要的环境数和训练长度验证：

- 不出现未处理的 EPA 异常。
- 不写入被污染的 Replay 转移。
- Actor/WM Loss 没有新增明显异常。
- 存活率与 Foot RMSE 没有明显退化。

如果选择保留 0.35 且 Action Mapping 未改变，优先考虑恢复现有 M4.2 Checkpoint。

如果最终决定更换到 0.25，需要明确说明旧 Actor、World Model、Replay 和优化器状态是否兼容；必要时从头训练。

**不要自动启动新的 5000 iterations 正式训练。**
