## 2. 核心研究目标

实现一个通用的多 Reference 强化学习训练框架，使同一个 Policy 能够根据不同 Foot/Root Goals 完成不同步长和步频的运动任务。

本轮完成：

- 通用 Multi-Reference Provider。
- 多 Motion Clips 加载。
- 每环境独立 Reference 采样。
- 每环境独立 Reference 时间索引。
- Replay/BPTT 多 Reference 一致性。
- 基于 M4.11-B1250 的迁移训练。
- 初始状态多样化课程。
- 三种直行步态的统一 Policy 训练。
- 未见步长、步频组合的泛化评估。

本轮使用离线生成的 Motion Clips。

不要求等待 M3.12 GPU Generator 优化完成，不直接接入 Online Generator 执行正式 RL 训练。

暂不开展转弯、转圈、后退及复杂地形训练。

## 4. M5.0.1 — Motion Library 建立

### 4.1 第一批训练 Reference

使用 M3.7.1 已有的三条直行 Reference。

| Clip | Step Length | Step Frequency | Yaw Rate |
| ---- | ----------: | -------------: | -------: |
| F1   |      0.14 m |      0.8333 Hz |        0 |
| F2   |      0.17 m |      1.0000 Hz |        0 |
| F3   |      0.20 m |      1.1111 Hz |        0 |

其中 Frequency 沿用 M3.7.1 左右脚交替落脚频率定义，不是单脚完整周期频率。

Reference 统一为 50 Hz。

优先使用已经生成并通过验收的原始档案，不重新生成 F2，不覆盖已有 Reference。

### 4.2 Reference 审计

逐条检查：

- 实际帧数及持续时间。
- 机器人模型与关节顺序。
- Quaternion 顺序。
- Root Pose / Velocity。
- Joint Position / Velocity。
- Foot Position / Orientation。
- Contact Labels。
- Liftoff / Touchdown Events。
- Reference Quality。
- Hand Position Reference。
- Foot Sole Offset。
- 初始姿态和末端接触状态。
- 关节限位及速度限位。
- 独立 FK 一致性。

明确区分运动学可行性与动力学可行性。

记录已有逆动力学和 CoP 诊断结果，但不在本轮修改 Reference。

不得强制将所有 Clips 裁剪至 F2 的 261 帧或 5.2 秒。

### 4.3 Motion Library Manifest

建立统一的 Motion Library 清单。

建议字段：

```python
MotionClip:
    clip_id
    file_path
    num_frames
    dt
    duration

    step_length
    step_frequency
    yaw_rate

    contact_events
    quality_summary
    valid_start_indices

    robot_model
    reference_version
    file_hash
    dataset_split
```

支持后续直接扩展：

- Turning Clips。
- Spinning Clips。
- Backward Clips。
- Standing Clips。
- Start/Stop Clips。
- Long-horizon Variable Gait Clips。
- Terrain-aware Clips。

不得在通用 Provider 内硬编码 F1/F2/F3 的数量、名字、时长或落脚次数。

## 5. M5.0.2 — Multi-Reference Provider

### 5.1 GPU 驻留参考库

训练开始时将所有训练 Reference 及必要派生数据加载至 GPU。

优先考虑：

- Packed Tensor + Clip Offset。
- Padded Tensor + Valid Mask。

根据实际代码选择实现。

避免：

- 每个环境重复加载 NPZ。
- 每个控制步从磁盘读取 Reference。
- 逐环境 Python 查询。
- 不必要的 CPU/GPU 传输。
- 重复计算静态 Reference FK。

### 5.2 每环境独立状态

每个环境维护：

```python
reference_id
reference_frame_index
reference_start_index
reference_length
episode_id
episode_step
```

支持不同环境同时跟踪不同 Clips。

环境 Reset 时，只更新该环境对应的 Reference ID 和时间索引。

不得影响其他环境的参考状态。

### 5.3 批量参考查询

建议接口：

```python
provider.get_current(
    clip_ids,
    frame_indices,
)

provider.get_future(
    clip_ids,
    frame_indices,
    future_offsets,
)
```

输出 Actor、Critic 和 Reward 实际需要的数据。

当前 Actor 保持：

```text
10 × 69 + 320 → 21
```

当前 Critic 保持原 970D 输入。

必须核对实际网络配置。

未来 10 个 Goal、0.1 s Goal Interval 和 32D Goal Feature 保持现有定义。

本轮不增加：

- Gait Phase 观测。
- Gait Frequency 观测。
- Step Length 观测。
- 完整上半身 Reference 输入 Actor。

Clip ID 只用于内部参考索引，不作为 Actor 的任务类别标签。

这样可以先验证现有 Foot/Root Goal Conditioning 的泛化能力。

### 5.4 Reference 末端处理

不同 Reference 具有不同长度。

必须正确处理：

- 当前帧查询。
- 未来 Goal 超出 Clip 末端。
- Critic Bootstrap 末端查询。
- 自然完成 Clip。
- 机器人提前跌倒。
- BPTT 跨 Episode 边界。

未来查询的末端处理优先沿用已经验证的 F2 Provider 语义，并扩展至所有 Clips。

禁止：

- Reference Index 越界。
- 将一个 Clip 的尾部连接到另一个 Clip 的首帧。
- 直接循环播放非周期 Clip。
- 在有效 Episode 中静默冻结 Reference 时间。
- 将 padding 产生的帧作为真实运动样本。
- 将正常完成 Clip 与跌倒混为同一种终止原因。

检查 Reference 末端的 Critic Bootstrap 和终止掩码是否符合当前训练目标。

## 6. M5.0.3 — Replay 与 BPTT 多 Reference 契约

这是本轮最重要的正确性检查之一。

当前 SuperMimic 在真实 Rollout、Replay 和 Imagined Rollout 中均需要查询 Reference。

Replay 中必须保存足够的参考身份信息，例如：

```python
reference_id
reference_frame_index
reference_version
episode_id
```

由于本轮使用不可变的离线 Motion Library，可以通过共享 Clip ID 和时间索引查询参考，不需要为每条 Transition 复制全部未来参考数据。

必须保证：

1. 真实 Rollout 使用正确的 Clip。
2. Reward 重算使用采集时的 Clip。
3. BPTT 使用相同 Reference ID。
4. Imagined Rollout 正确推进对应 Clip 的时间索引。
5. Critic Bootstrap 查询正确的未来目标。
6. Episode Reset 后旧 Transition 不会引用新 Episode 的 Clip。
7. 不同 Reference 不会出现跨环境数据串扰。
8. Hand Position Reference Cache 与 Clip ID 正确关联。
9. WM 的动作和状态序列不会跨 Episode 拼接。
10. 参考库在本次训练期间保持不可变。

核对 BPTT Horizon=16 与未来 Goal 查询的最大跨度。

保留 M3.11 已验证的参考版本一致性思想，为未来 Online Provider 接入预留统一接口。

本轮不需要重新实现 Online Snapshot Pool，但不能破坏后续接入能力。

其他 Replay、UTD、Batch Size 和优化器参数优先沿用 M4.11 实际配置。

不得仅根据旧 Prompt 推测实际配置。

Actor LR 在本轮联合训练中固定为 5e-5。WM/Critic 使用重新建立的原调度，记录实际生效 LR。

### 8.2 Stage 0 — WM/Critic Adaptation

训练预算：1000 iterations。

初始化 Reference 采样概率：

|  F1 |  F2 |  F3 |
| --: | --: | --: |
| 20% | 60% | 20% |

本阶段：

- 冻结 Actor 参数。
- 冻结 Actor 使用的输入归一化器，避免 Actor 实际行为改变。
- 使用 B1250 进行真实 Newton Rollout。
- 建立新的多 Reference Replay Buffer。
- 更新 WM。
- 更新 Critic。
- 允许 WM/Critic 独立归一化器合理适应新数据。

重点检查：

- WM 对 F1/F2/F3 的 1/4/8 步预测误差。
- Critic Value Target。
- Critic Loss。
- Real/Imagined Reward Gap。
- 每个 Clip 的有效采样数量。
- F2 原有动力学预测能力是否退化。

如果多个新步态只能产生极短且高度重复的失败轨迹，应报告采样覆盖问题，不单纯以 WM Loss 下降作为适应成功依据。

适应结束后保存独立 Checkpoint，再开放 Actor 更新。

### 8.3 Stage 1 — 初步多步态学习

联合训练 iterations 1–1000：

|  F1 |  F2 |  F3 |
| --: | --: | --: |
| 20% | 60% | 20% |

优先保持 F2 已有控制能力，同时学习新步态。

开启 Actor、WM、Critic 联合训练。

### 8.4 Stage 2 — 扩大新步态占比

联合训练 iterations 1001–3000：

|  F1 |  F2 |  F3 |
| --: | --: | --: |
| 30% | 40% | 30% |

验证 F1 和 F3 是否逐渐形成稳定步态。

重点监控 F2 是否发生灾难性遗忘。

### 8.5 Stage 3 — 均衡多步态训练

联合训练 iterations 3001–6000：

|  F1 |  F2 |  F3 |
| --: | --: | --: |
| 1/3 | 1/3 | 1/3 |

最终获得一个统一 Policy。

所有 Reference 采样概率均指 Episode Reset 时的 Clip 选择概率，而不是实际 Replay Transition 占比。

由于不同 Reference 的 Episode 长度及失败率不同，必须记录：

- 每个 Clip 的 Reset 次数。
- 每个 Clip 的有效 Transition 数。
- 实际 Replay 样本占比。
- 完整任务成功率。
- 平均 Episode Length。

不得将配置采样概率直接当作实际训练数据分布。

如果出现严重的数据失衡，先报告原因，再决定是否引入按 Reference 分层采样。不要静默修改 Replay 采样机制。

上述阶段边界为预设课程。在阶段切换前检查任务完成率及数值稳定性；若明显退化，应保留 Checkpoint 和诊断结果，不盲目增加任务难度。

## 9. 初始状态随机化课程

M4.11 已经表明，正常初态的跟踪效果不能代表实际状态恢复能力。

因此本轮在多 Reference 训练基础上，适量引入初始状态偏差。

首先检查 M4.11 训练中实际使用的 Reset 随机化配置。

所有新增随机化必须建立在真实配置核对基础上，避免重复叠加。

沿用 M4.11 独立评估的目标范围：

| 随机化对象            | 目标范围           |
| --------------------- | ------------------ |
| Root X/Y              | 各 ±0.02 m         |
| Root Height           | +0.006 至 +0.012 m |
| Root Roll/Pitch       | 各 ±1°             |
| Root Yaw              | ±3°                |
| Joint Position        | 各 ±0.01 rad       |
| Root Linear Velocity  | 各 ±0.02 m/s       |
| Root Angular Velocity | 各 ±0.05 rad/s     |
| Joint Velocity        | 各 ±0.10 rad/s     |

采用渐进课程：

| 联合训练阶段 | 使用新增初态偏差的 Episode 比例 |                  偏差范围 |
| ------------ | ------------------------------: | ------------------------: |
| 1–1000       |                              0% |            保持原训练配置 |
| 1001–1500    |                              0% | 先适应新的 Reference 分布 |
| 1501–3000    |                             25% |            目标范围的 50% |
| 3001–3500    |                             25% |            目标范围的 50% |
| 3501–6000    |                             50% |    逐步扩大至完整目标范围 |

避免在同一个训练迭代同时大幅改变 Reference 采样比例和初始状态偏差范围。

训练随机化使用独立随机种子，不使用最终 Evaluation 的固定初态作为训练样本。

本轮暂不引入：

- Random Reference Start Phase。
- 外力 Push。
- 摩擦系数随机化。
- 质量和惯量随机化。
- PD 参数随机化。
- 传感器噪声随机化。

所有 Clips 继续从各自合法的起始状态开始，避免随机起始相位与 Startup Smoothstep、支撑状态不一致。

新增初态随机化与多 Reference 数据扩展共同构成本轮课程。因此本轮不单独宣称初态恢复能力的改善完全来自多 Reference 训练。

## 10. 训练前正确性验收

### 10.1 Provider 单元测试

至少覆盖：

- 单条 F2 新旧 Provider 等价。
- 混合 F1/F2/F3 查询。
- 不同 Clip 长度。
- Future Goal Gather。
- Reference 末端。
- 不同环境异步 Reset。
- Reference ID 更新。
- Episode ID 更新。
- Hand Position Reference Cache。
- GPU 批量查询。
- 无跨环境数据串扰。
- 无跨 Clip 索引错误。

### 10.2 Replay / BPTT 测试

构造混合 Clips 的真实 Transition 和训练 Batch。

检查：

- Replay Reward 重算。
- Actor Goal 重算。
- Critic Goal 重算。
- BPTT 未来 Reference。
- Bootstrap Reference。
- Episode Boundary Mask。
- 所有 Reward、Loss 和 Gradient 有限。

特别测试同一个环境连续 Reset 到 F1、F3、F2 后，历史 Replay 仍能正确查询原 Clip。

### 10.3 CUDA Smoke Test

按以下规模逐步验证：

```text
8 Envs
  ↓
32 Envs
  ↓
256 Envs
```

覆盖：

- Checkpoint 加载。
- 多 Reference Rollout。
- 异步 Reset。
- WM/Critic Adaptation。
- Actor BPTT Update。
- Critic Update。
- Checkpoint 保存及恢复。
- 不同长度 Clip 的正常终止。

确认无 EPA、无效 Replay、非有限梯度或严重物理异常。

### 10.4 性能检查

比较：

- 原单 Reference Provider。
- 新 Multi-Reference Provider（仅 F2）。
- 新 Multi-Reference Provider（F1/F2/F3 混合）。

统计：

- Collection FPS。
- Training FPS。
- Reference Query Time。
- Replay Sampling Time。
- GPU 显存。
- Learning Time。

多 Reference 查询不应引入类似 M3.11 在线生成器的大量额外计算开销。

如果性能下降明显，先定位 Provider 的数据组织和索引瓶颈。

## 13. 未见参数泛化实验

F1、F2、F3 的步长与步频同时变化，不能证明两种参数已经独立解耦。

因此需要准备额外的 Held-out Reference。

建议候选：

| Clip | Step Length | Step Frequency | Yaw Rate |
| ---- | ----------: | -------------: | -------: |
| H1   |      0.14 m |      1.1111 Hz |        0 |
| H2   |      0.20 m |      0.8333 Hz |        0 |
| H3   |     0.155 m |        0.95 Hz |        0 |
| H4   |     0.185 m |        1.05 Hz |        0 |

这些参数只是候选，需先经过 Motion Generator 的运动学验收。

优先使用与训练 Clips 相同的 M3.7.1 生成方法和源 Motion Prior，避免生成算法差异干扰泛化结论。

如果采用 M3.10 生成 Held-out Reference，应明确说明同时存在生成器版本的分布差异。

所有 Held-out Clips：

- 不进入训练库。
- 不进入 Replay。
- 不参与 Normalizer 更新。
- 不参与课程难度调整。
- 不用于 Best Checkpoint 筛选。
- 在模型选定后用于最终泛化评估。

如果某组候选无法通过生成器验收，记录原因，可在训练开始前确定替代组合，不得根据 Policy 测试表现事后筛选。

本轮重点验证：

- 未见步长。
- 未见步频。
- 未见步长与步频组合。
- 不同运动速度。
- 不同初始状态下的泛化。

不要将有限数量的 Held-out Clips 成功解释为整个连续步态参数空间已经得到验证。
