# M4.7 — Startup Shock Correction & Upper-body Smoothness Ablation

## 一、实验背景与目标

当前项目基于 SuperMimic World Model + BPTT + Asymmetric Actor-Critic，在 Isaac Lab 3.0 + Newton/MJWarp 中训练 Roban 21-DoF 人形机器人，实现基于 Foot/Root Goals 的全身运动控制。

目前已完成：

- M4.3：Swing-Aware Reward，实现完整 F2 四步跟踪。
- M4.4：Action Mapping 消融，确认保留 Hard Clamp。
- M4.5：Upper-body Motion Prior 初步消融。
- M4.5.1：上半身先验与步态鲁棒性诊断。
- M4.6：`body_prior_weight=0.00/0.02/0.05/0.10` 的 Fresh Start 权重消融，以及上半身运动平滑性诊断。

请优先阅读最新的 `m4.6_report.md`，确认实际文件路径和实验数据。

M4.6 的重要发现：

1. M4.3 Best 仍然是当前默认步态基线。
2. `body_prior_weight=0.02` 可以改善足位精度与上半身平滑性，但没有通过 CUDA 名义四步验收。
3. `body_prior_weight=0.05` 的第 4500 轮可以完成四步，但腰部误差、力矩饱和及扰动下的加速度尖峰较高。
4. 七份 Policy 的最大手臂加速度均出现在第一个控制周期的右肘 `zarm_r4_joint`。
5. 名义起态的右肘位置约为 −1.813 rad，首个 PD Target 与实际关节位置相差 0.711–1.689 rad。
6. 第一个 20 ms 控制周期内，右肘角速度从接近 0 升至 27.2–51.4 rad/s。
7. 排除起步阶段后，连续行走过程中仍然存在较大的关节加速度和 Jerk。

本次实验有三个核心目标：

- 解决 Reset 后第一个控制周期的上半身冲击问题。
- 增加针对上半身的动作平滑奖励。
- 验证不使用上半身轨迹跟踪奖励时，Policy 能否自主学习平滑、合理且具有动态平衡能力的上半身运动。

本次不再搜索 Body Prior 权重，不进行 Fine-tuning，正式训练统一采用 Fresh Start。

## 六、保证训练与执行动力学一致

如果最终采用启动阶段 PD Target 平滑，不能只在 Evaluation 中增加动作过滤。

必须保证：

\[
\text{Newton 执行}
\equiv
\text{Replay 动作语义}
\equiv
\text{WM 动作输入语义}
\equiv
\text{BPTT 想象执行}
\]

重点检查：

- WM 是否使用实际执行的 effective action。
- Replay 是否正确保存实际执行指令。
- Actor Raw Action 与 Effective Action 是否能够明确区分。
- 启动阶段所需的 Reset Pose、Elapsed Time、History 是否可从 BPTT 起点恢复。
- 随机抽取 Replay Window 时是否能正确恢复启动状态。
- Hard Clamp 与 Smoothstep 的执行顺序是否一致。
- BPTT 中的动作变换是否可微。
- 是否存在训练使用原始 Action，但 Newton 实际执行平滑后 Action 的动力学错配。

优先保持原 Actor/WM/Critic 网络维度。

允许增加必要的辅助状态或 Replay 元数据，但不能未经验证就修改网络结构或将 Reference 上半身目标泄漏给 Actor。

如果无法保证这些契约一致，不允许直接将启动过滤器纳入正式训练。

# Phase II — M4.7.2 Upper-body Smoothness Reward

## 七、新增上半身平滑奖励

本轮使用上半身原始动作二阶差分作为主要平滑正则：

\[
r_{\mathrm{upper\_smooth},t}
=
-\frac{1}{N_{\mathrm{upper}}}
\sum_{j\in\mathcal J_{\mathrm{upper}}}
(a_{j,t}-2a_{j,t-1}+a_{j,t-2})^2
\]

总奖励变为：

\[
r_t^{\mathrm{new}}
=
r_t^{\mathrm{M4.3}}
+
\Delta t\,w_{\mathrm{body}}r_{\mathrm{body},t}
+
\Delta t\,w_{\mathrm{smooth}}r_{\mathrm{upper\_smooth},t}
\]

其中：

- `r_body` 沿用 M4.5/M4.6 的原有定义。
- `r_body` 和 `r_upper_smooth` 在上式中均为尚未乘配置权重和 dt 的分项。
- `dt=0.02 s`。
- `N_upper=9`。
- 新增配置字段建议为 `upper_action_smoothness_weight`。

注意现有 Reward 的 dt 缩放位置，不能重复乘以 dt。

本次不增加：

- Joint Acceleration Penalty。
- Joint Velocity Penalty。
- Joint Jerk Penalty。
- Soft Posture Prior。
- Phase-conditioned Arm Prior。
- Touchdown Velocity Penalty。

上述方法留待后续独立消融。

### 7.1 上半身关节范围

核对真实关节顺序及名称。

预计包含：

- `waist_yaw_joint`
- `zarm_l1_joint`
- `zarm_l2_joint`
- `zarm_l3_joint`
- `zarm_l4_joint`
- `zarm_r1_joint`
- `zarm_r2_joint`
- `zarm_r3_joint`
- `zarm_r4_joint`

禁止直接假设 Action Tensor 中的固定索引。

应通过现有关节映射获取正确索引并编写回归测试。

不对下肢增加新的平滑惩罚。

### 7.2 动作历史管理

正确管理：

\[
a_t,\quad a_{t-1},\quad a_{t-2}
\]

要求：

- Newton 真实 Rollout 和 WM/BPTT 使用相同定义。
- 不跨 Episode 计算动作二阶差分。
- Reset 时使用合法的历史初始化与有效历史掩码。
- 不对不存在的历史动作产生虚假平滑惩罚。
- Replay Window 的首个想象步骤能够访问真实前两步动作。
- BPTT 内部新生成的动作必须保留梯度。
- 不因错误的 `detach()` 破坏二阶差分奖励的跨时间梯度。
- 保留原 Action Rate Reward，不能用新增项直接替换它。

新增平滑奖励以 raw action 为对象，同时记录：

- Raw Action 二阶差分。
- Effective Action 二阶差分。
- Hard Clamp 后 PD Target 二阶差分。
- 启动过渡后实际 PD Target 二阶差分。
- 真实关节加速度与 Jerk。

不能仅根据 raw action 更平滑就认定实际运动一定更加平滑。

### 7.3 Reward 回归测试

至少验证：

1. 常量 Action 序列的平滑惩罚为零。
2. 匀速线性变化的 Action 序列二阶差分为零。
3. 突变和高频振荡 Action 产生更大惩罚。
4. 仅改变下肢 Action 不影响新增奖励。
5. 权重设为零时，奖励与原配置完全一致。
6. Reset 边界不产生虚假惩罚。
7. 真实采集与 WM 想象中的分项奖励数值一致。
8. 梯度有限，且与解析梯度或有限差分一致。

## 八、确定 Smoothness Reward 权重

不要直接照搬 Body Prior 的权重。

使用已有 M4.3/M4.6 冻结轨迹和真实 Replay 起点进行离线权重标定。

建议检查候选：

```text
upper_action_smoothness_weight:
0.01
0.02
0.05
0.10
```

此处只进行离线数值及梯度审计，不对四个权重分别启动正式训练。

M4.6 已有数据表明，上半身 Action 二阶差分 RMS 约为 0.28–0.47，应根据真实奖励尺度进行权重选择。

统计：

- 未加权 Smoothness Cost。
- 加权后每步奖励贡献。
- RMS、P95、P99、Max。
- 与 Foot Reward 的数值比例。
- 与原 Action Rate Penalty 的数值比例。
- 与 Torque Penalty 的数值比例。
- 不同相位下的奖励贡献。

进行 BPTT 梯度分解：

\[
g_{\mathrm{foot}}=\nabla_\theta J_{\mathrm{foot}}
\]

\[
g_{\mathrm{smooth}}=\nabla_\theta J_{\mathrm{smooth}}
\]

\[
g_{\mathrm{body}}=\nabla_\theta J_{\mathrm{body}}
\]

分别统计梯度范数、余弦相似度和上/下肢动作通道梯度。

重点检查：

- 初始双足支撑。
- Swing。
- Touchdown。
- 扰动恢复。

选择一个弱至中等的平滑正则权重。

初步希望其 Actor 参数梯度范数处于足部奖励梯度范数的约 1%–5%，作为工程筛选参考，而非必须满足的理论标准。

不能只依据平均奖励贡献判断梯度强度。

最终只选定一个 `w_smooth` 用于下面两组正式平滑奖励实验，并记录选择依据。
