# M4.0 — SuperMimic 网络结构与训练配置核查

请检查当前 SuperMimic 仓库的实际代码，以及此前 **400 iterations 的 M4.0 Roban F2 训练配置**。

**本次只进行代码审查和配置核对，不修改代码、不启动训练、不进行课程学习。**

## 1. Action Mapping

确认 Actor 输出的 21 维关节动作是否以**默认关节姿态**为中心：

\[
q*{\mathrm{target}}=q*{\mathrm{default}}+k_a a_t
\]

重点确认：

- `q_default` 的来源及具体含义。
- Action Scaling 和 PD Target 的实际计算公式。
- 是否使用了随时间变化的 `q_ref(t)` 作为动作中心。

## 2. 非对称 Actor–Critic 架构

确认当前训练是否采用 **Asymmetric Actor–Critic**：

- Actor 和 Critic 是否具有不同的观测输入。
- 是否仍使用 SuperMimic 的 Motion Encoder、Shared Decoder、World Model 和 BPTT 训练结构。
- Critic 是否使用特权信息，而 Actor 不使用。

## 3. Actor / Critic 输入配置

核查实际网络输入是否符合我们此前讨论的设计：

**Actor：**

- 本体观测（Proprioception）。
- 历史本体观测。
- 未来足部目标轨迹。
- 必要的 Contact / Phase / Root Goal 信息。
- 不直接接收完整未来关节 Reference。

**Critic：**

- 完整机器人状态及本体观测。
- 完整全身 Motion Reference（Root、关节、足部等）。
- 必要的仿真特权信息。

请逐项列出实际输入、维度、数据来源及预处理方式。

**特别注意：此前 M4.0 报告提到 Critic 输入为 55 维完整状态、25 维仿真上下文和 320 维目标，同时关闭了额外的全身 Reference 输入。请重点核实当前 Critic 是否真的接收完整机器人 Reference，不要把未来 Foot/Root Goal 误认为完整全身 Reference。**

## 4. 核查此前 400 Iterations 的实验配置

读取 M4.0 的实际训练配置、历史日志及 Checkpoint 元数据（如有），确认**已经完成的 400 iterations** 是否使用了上述：

1. Default-centered Action Mapping。
2. Asymmetric Actor–Critic。
3. Actor 本体观测 + 未来足部轨迹。
4. Critic 完整机器人 Reference + 本体/特权观测。

必须区分：

- 当前源码默认配置。

不要仅凭当前源码推断历史实验设置。
