# M4.3 — Swing-Aware Reward Reconstruction 与 World Model 梯度可靠性验证

## 0. 任务目标

当前项目为 Roban 21-DoF 人形机器人，基于 SuperMimic 的 World Model + BPTT + Asymmetric Actor–Critic，实现 Foot/Root Goal 驱动的 F2 Motion Tracking。

请在 M4.2 v2/v3 实验基础上完成 **M4.3 奖励函数重构、正式训练、独立评估以及 WM 局部梯度可靠性验证**。

本轮最终目标不是让机器人存活 5.2 s，而是让机器人能够根据 F2 Reference：

1. 在首次计划摆动阶段主动抬起左脚。
2. 实现由双足支撑到单足支撑的切换。
3. 完成首次有效 Touchdown。
4. 在此基础上提高 Foot/Root Tracking 精度。
5. 避免重新出现大规模 Action Clamp 和不可信 WM 梯度。

请实际修改代码、运行测试、完成正式训练并提交实验报告。不要仅生成方案。

## 2. M4.2 v3 的核心诊断结论

已有报告确认：

### 2.1 机器人没有真正完成摆腿

第 5000 轮：

- 首次 Swing 阶段左脚约 87.5%–92.5% 时间仍在承重。
- 左脚最大抬升仅约 5 mm。
- First Swing Success：0/3。
- First Touchdown Success：0/3。
- 存活率虽然为 100%，但依赖小幅换支撑及带载滑动。
- Target Clamp Ratio 约 25%。

### 2.2 Reward 存在梯度衰减

当前 Swing Position Reward：

\[
r_{\mathrm{swing}}=
\exp\left(-\frac{\|p_f-p_f^*\|^2}{0.08^2}\right)
\]

当 Foot Error 达到 0.2–0.4 m 时，梯度迅速衰减。

旧 Touchdown Reward 仅在四个事件帧生效，累计激励极弱。

旧奖励中 Upright 和 Survival 约占最终净回报的 63.8%。

### 2.3 WM 局部梯度存在显著问题

M4.2 v3 的有限差分诊断中：

- WM 与 Newton 局部 Foot Reward 斜率符号一致率：54.8%。
- Pearson r：0.165。
- 第 5000 轮 WM 的 8-step Foot RMSE：约 0.0874 m。
- 存在部分 WM 预测奖励上升、但实际 Newton 奖励下降的动作方向。

### 2.4 降低 Actor LR 有帮助

M4.2 v3 的短续训对照：

| 方案 | Foot RMSE | Root XY RMSE |
|---|---:|---:|
| 原学习率 | 0.262 m | 0.193 m |
| 奖励宽度扩大 | 0.241 m | 0.138 m |
| Actor LR=5e-5 | 0.149 m | 0.105 m |

低学习率方案出现约 5.92 cm 的抬脚，但连续卸载仅 0.06 s，仍未完成有效 Touchdown。

本次 M4.3 必须以这些诊断为依据，不能只简单放大 Swing Reward 权重。

## 3. 任务一：重构 Swing-Aware Reward

这是本次最主要的代码修改。

请先检查当前 `supermimic/roban_task.py` 中所有 Reward 的实现、归一化、时间权重及 BPTT 梯度路径。

要求新奖励函数满足：

- 有效鼓励 Swing Foot 主动离地。
- 对较大足位误差仍保留恢复梯度。
- 鼓励 Swing Foot 接近计划落脚位置。
- 在正确时间完成 Touchdown。
- 保持 Stance Foot 稳定支撑。
- 不鼓励双脚同时腾空、带载滑动或无意义的反复抬腿。
- Newton 与 WM 使用相同的可微 Reward 定义。

### 3.1 Swing Position：使用长尾奖励

优先考虑替换为：

\[
r_{\mathrm{swing,pos}}=
\frac{1}{1+\left(\frac{\|p_f-p_f^*\|}{\sigma}\right)^2}
\]

建议从 `σ=0.12 m` 作为候选开始，并与 `0.08 m`、`0.16 m` 做梯度曲线对比。

也可以考虑 Huber 型位置惩罚，但必须解释最终选择。

要求：

1. 绘制 0–0.5 m 的 Reward 和梯度曲线。
2. 比较旧指数形式和新长尾形式。
3. 检查 0.15–0.4 m 的恢复梯度。
4. 确保位置误差减小时梯度方向正确。
5. 使用计划 Swing Mask，只在对应脚的 Swing 阶段生效。
6. 当没有 Swing Foot 时，归一化不能导致除零或异常激励。

不能只是增大 Reward 权重。

### 3.2 Swing Clearance：连续鼓励摆动脚离地

新增或重构可微的 Swing Clearance 项。

使用 F2 参考中的足底高度、Swing Phase 和地面高度，建立随相位变化的目标。

要求：

- 摆动初期鼓励卸载及抬脚。
- 摆动中期鼓励达到参考足部高度。
- 摆动末期鼓励自然下降准备落脚。
- 不鼓励整段 Swing 始终高抬脚。
- 不鼓励提前触地。
- 不依赖不可微的硬接触力阈值向 Actor 反传。

可以使用 Softplus、Huber 或其他连续可微函数来惩罚摆动脚高度不足。

不得引入与 F2 Reference 明显冲突的人工足部高度轨迹。

需要验证当前 F2 的足底高度、碰撞几何和地面坐标系一致。

### 3.3 Swing Contact：减少摆动脚持续承重

M4.2 v3 发现，原软接触代理对真实接触的解释并不准确。

例如，一部分真实承重样本的软接触预测仍较低。

请先评估当前：

\[
b(h,v)
\]

与真实 Newton Foot Contact Force 的对应关系。

如果继续使用软接触代理，需要重新校准它在：

- 正常双足支撑。
- 首次 Swing。
- 带载滑动。
- 足部离地。
- Touchdown。

五类状态下的判别与梯度行为。

鼓励 Swing Foot 离地时，不能破坏 Stance Foot 的支撑要求。

真实 Newton 接触力可用于诊断和独立评估，但不能直接当作 WM BPTT 中不存在的可微输入。

### 3.4 Touchdown：从稀疏事件奖励改为连续窗口奖励

旧 Touchdown Reward 只在计划落脚事件帧生效，需要重构。

利用 F2 的：

- Planned Touchdown Time。
- Planned Landing Position。
- Swing Phase。
- Planned Contact Schedule。

设计具有时间窗的连续可微落脚引导。

建议在 Swing 后半段逐渐提高对计划落脚点的跟踪要求。

可以使用平滑时间窗或 Smoothstep 等连续权重：

\[
r_{\mathrm{landing}}
=
w(\phi)\cdot
r_{\mathrm{landing,pos}}
\]

但需要确保：

- 不鼓励提前落脚。
- 不鼓励为了接近落脚点而忽略抬脚过程。
- 不依赖单个事件帧产生几乎全部梯度。
- 落脚时间和位置目标与 F2 完全一致。
- 结合摆动脚离地和支撑切换约束，避免双脚滑向落脚点。

所有奖励均应使用同一时间尺度和权重约定。

### 3.5 Stance 与身体稳定性

保留必要的：

- Stance Foot Position。
- Upright。
- Survival。
- Slip。
- Joint Limit。
- Torque。
- Collision。
- Self Collision。
- Action Rate。

但重新检查各项贡献，避免 Upright/Survival 对成功摆腿形成压倒性优势。

尤其不能简单降低 Survival 以至于机器人学会通过跌倒终止来规避 Swing 惩罚。

本轮优先解决首次摆腿和落脚，Root Tracking Reward 如需调整，请单独列为后续消融，不要未经验证同时改动。

## 6. 任务四：验证 World Model 局部梯度可靠性

本任务非常重要，不能仅报告 WM Loss 下降。

请沿用并完善 M4.2 v3 已实现的 Newton 有限差分诊断代码。

### 6.1 梯度验证方法

对真实 Newton 状态 \(s_t\) 和动作 \(a_t\)，比较：

\[
g_{\mathrm{WM}}
=
\nabla_a r(f_{\mathrm{WM}}(s_t,a))
\]

与真实 Newton 有限差分得到的局部奖励变化：

\[
g_{\mathrm{Newton},i}
\approx
\frac{
r(s_{t+1}^{a+\epsilon e_i})-
r(s_{t+1}^{a-\epsilon e_i})
}{2\epsilon}
\]

必要时使用方向导数而非逐维差分，以减少实验成本。

请验证：

- 足部奖励梯度。
- 新 Swing Clearance 梯度。
- 新 Landing Reward 梯度。
- 总 Reward 梯度。
- 仅未裁剪动作维的梯度。
- 不同接触阶段的梯度。

真实 Newton 正负扰动必须从相同的完整物理状态开始，并尽可能恢复接触及求解器暖启动状态。

不同 Reward 使用相同的参考时钟、坐标系与状态定义。

### 6.2 梯度准确性指标

至少记录：

- Gradient Sign Agreement。
- Cosine Similarity。
- Pearson Correlation。
- Gradient Magnitude Error。
- WM 预测改善但 Newton 实际恶化的比例。

对数值幅度无法可靠辨识的方向单独统计，不允许把它们简单算作方向一致或不一致。

对多种扰动幅度进行敏感性测试，排除有限差分数值误差。

覆盖双足支撑、首次 Swing、Touchdown 窗口、单腿支撑、高动作变化及 Clamp 附近状态。

使用多条真实 Rollout、多个种子和足够的有效方向，提供样本数及置信区间。

### 6.3 分阶段 WM 验证

至少在以下 Checkpoint 执行：

- Iter 1000。
- Iter 2000。
- Iter 3000。
- Iter 5000。

分别评估：

1. 同策略采样分布上的 WM 预测。
2. 固定公共测试数据集上的 WM 预测。
3. 局部动作梯度的方向一致率。
4. 不同足部误差区间内的梯度可靠性。

必须区分 WM 的状态预测精度与梯度精度。

与 M4.2 v3 的 54.8% 方向一致率进行对照时，尽量沿用相同的有限差分口径和公共测试集。

如果新 Reward 的梯度形状改变，需要分别比较：

- 相同旧 Reward 下的新旧 WM 动力学梯度质量。
- 相同新 Reward 下的新旧 WM 的奖励梯度质量。

避免把 Reward 改变造成的梯度差异误判成 WM 本身变好。

### 6.4 BPTT 梯度审计

检查：

- Swing/Touchdown 梯度是否能够稳定到达 Actor。
- 是否存在大量 Clamp 造成的零梯度。
- Critic Bootstrap 与 Swing/Touchdown 梯度是否冲突。
- BPTT 更新方向是否能够改善真实 Newton Reward。
- Imagined Rollout 中预测的 Foot Lift 是否会在真实 Newton 中出现。

如果发现明显错误梯度，需要量化其范围和严重程度，不得只根据训练 Loss 推断。
