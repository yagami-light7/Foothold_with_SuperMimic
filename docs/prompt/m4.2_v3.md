# M4.2 v3 — Asymmetric Actor–Critic 训练失效诊断

## 一、任务背景与目标

当前项目采用 SuperMimic 范式，在 Isaac Lab 3.0 + Newton/MJWarp 环境下，训练 Roban 21-DoF 人形机器人跟踪 F2 Footstep Reference。

网络为 Asymmetric Actor–Critic：

**Actor**

- 输入：10×69 维 Proprioception History + 320 维未来 Foot/Root Goals。
- Motion Encoder + Shared Decoder。
- 输出：21 维 Linear Action。
- Action Mapping：固定站姿中心 + Action Scale + 关节目标 Clamp。

**Critic**

- 输入：当前完整状态、物理上下文、未来 Foot/Root Goals，以及额外的未来全身 Reference。
- 预期维度为 970。
- 通过价值估计支持 BPTT 中的长期回报优化。

**World Model**

- 使用真实 Newton Replay 监督学习动力学。
- Actor 通过冻结 WM 的 imagined rollout 执行 BPTT。
- WM 与 Actor 交替更新。

当前 Action Scale：

\[
\alpha=0.35\frac{\tau\_{\max}}{K_p}
\]

已经完成 EPA_HORIZON 异常隔离修复。

**本次任务只检查当前 Foot/Root Goal 驱动的非对称 AC 训练，不进行 Full-body SuperMimic 基线，不更换机器人、不修改 F2 Reference。**

核心目标是回答：

> 为什么 Actor 在经过 5000 iterations 后能够存活完整 F2 时长，却没有完成首次计划摆腿和落脚，且足部跟踪误差持续较大？

请定位主要原因并提出有实验证据的修复方案。

6. 最终策略 `standing_rate=0`，但 `survival_rate=1`，需要确认终止条件和评估指标是否合理。

## 三、任务一：完整审计 Reward、Termination 与评估指标

**这是最高优先级，先完成该任务再进行训练修改。**

### 1. Reward 审计

检查当前 F2 任务所有 Reward 的实际实现和配置。

对于每一个 Reward Term，输出：

- 名称与权重。
- 数学表达式。
- 输入状态及坐标系。
- 使用真实状态还是 WM 预测状态。
- 是否对 Actor Action 可微。
- 训练过程中每项奖励的平均贡献。
- 在第 1000、3000、5000 轮策略下的贡献。
- 奖励梯度对 Actor 的贡献。

重点检查：

- Swing Foot Position Tracking。
- Stance Foot Tracking。
- Foot Contact / Touchdown。
- Root Position / Orientation Tracking。
- Upright / Survival。
- Action Rate。
- Joint Limit。
- Torque / Saturation。
- Foot Slip。

判断是否存在：

**不完成计划摆腿和落脚，但通过保持存活、维持部分接触或其他行为获得较高累计奖励的策略。**

不要仅依据 Reward 权重判断，必须统计实际贡献和梯度。

特别检查各项奖励的时间归一化与尺度，区分：

- 单步平均奖励。
- Episode 累计奖励。
- 按完整 5.2 s 归一化的奖励。

### 2. Termination 审计

检查实际 Newton 环境和 imagined rollout 的终止条件。

核查：

- 根部高度下限。
- 躯干倾角。
- 非法接触。
- 关节位置、速度异常。
- 物理异常。
- Episode Timeout。
- F2 Motion End。

重点回答：

**为什么最终策略能够存活 5.2 s，但 `standing_rate=0`？**

检查 `standing_rate` 是否属于独立评估标准，与实际 Termination 不一致。

区分机器人正常站立、双脚正常行走、倒地但未触发终止、利用不合理姿态持续存活等不同情况。

不要直接收紧 Termination，先完成日志和视频确认。

### 3. Touchdown 检测审计

检查：

- 足底接触力阈值。
- Swing 起止事件定义。
- 足部离地持续时间。
- 最小抬脚高度。
- 落脚位置和时间容差。
- 左右脚索引与 F2 接触标签。
- 物理子步接触采样方式。

需要明确：

**Matched Touchdowns=0 是因为机器人确实没有摆腿落脚，还是事件检测条件不正确？**

使用真实接触力和足底高度时间序列逐帧验证。

## 五、任务三：专项检查 Asymmetric Actor–Critic

本任务重点研究非对称 Critic 是否真正为 Actor 提供了有价值的长期优化信号。

### 1. Critic 输入验证

核查实际运行中的 Critic：

- 输入维度是否确实为 970。
- 是否使用当前完整物理状态。
- 是否使用未来 Full-body Reference。
- 是否使用仿真特权上下文。
- 全身参考与 Foot/Root Goal 的时间是否同步。
- 是否存在 Reference 索引偏移、坐标系错误或归一化问题。

确认这些额外信息没有错误泄漏到 Actor 观测中。

### 2. Critic 价值估计质量

从真实 Newton Replay 中采样状态。

对比：

\[
V\_{\mathrm{critic}}(s_t,g_t)
\]

与同一冻结 Policy 在真实 Newton 环境中获得的 Monte Carlo Return。

分开统计：

- 双足支撑阶段。
- 首次 Swing 阶段。
- Touchdown 附近。
- 临近跌倒的状态。
- 临近 Reference 结束的状态。

报告 Value Bias、RMSE、相关性及不同时间段的误差。

检查 Critic 是否高估某些无法完成落脚、但能维持存活的行为。

### 3. Actor Loss 梯度分解

在相同 Replay 起点和冻结网络参数下，将 Actor BPTT 梯度分解为：

- Foot/Root Tracking Reward。
- Upright / Survival。
- Action Regularization。
- Critic Bootstrap。
- 其他主要 Reward Terms。

分别报告：

- Gradient Norm。
- 梯度有限性。
- 不同梯度之间的 Cosine Similarity。
- Critic Bootstrap 梯度与 Foot Tracking 梯度是否冲突。
- 裁剪关节的梯度是否明显弱于非裁剪关节。

注意：必须根据实际 Actor Loss 的计算图进行分解，不能将不存在于 Actor Loss 的 Critic 拟合损失误认为 Actor 梯度。

### 4. 诊断性消融

先在冻结网络和相同 Replay Batch 上测试：

A. 原始 Asymmetric AC 完整 Actor Loss。

B. 不使用 Critic Bootstrap，只保留 BPTT Reward。

C. 暂时屏蔽 Survival/Upright 奖励梯度，只观察 Foot Tracking 梯度。

这些实验先进行**梯度比较和短时单步更新诊断**，不直接运行长训练。

如果发现 Critic 或某项 Reward 明确主导了错误更新方向，再设计独立短训练消融。

## 六、任务四：World Model 与 BPTT 可靠性

重点检查 Actor 开始更新以后，World Model 是否能够准确预测 Actor 实际执行的动作。

### 1. 训练数据分布

检查前 1000 轮 WM-only 阶段：

- Actor 输出的原始动作分布。
- 探索噪声的真实幅度。
- Replay 中动作的实际分布。
- WM Action Normalizer 的统计量。
- 与 Iter 1500–5000 动作分布的差异。

尤其检查是否出现：

**WM 在接近零动作的数据上训练，但 Actor BPTT 更新后进入此前没有覆盖的大动作区域。**

### 2. World Model 预测误差

使用同一组独立真实 Newton 轨迹作为测试集。

测量：

- One-step State Error。
- 4-step / 8-step State Error。
- Foot Position Prediction Error。
- Root Position / Orientation Error。
- Reward Prediction Error。
- Termination Prediction Error。

同时区分：

- Clamp 触发状态。
- Clamp 未触发状态。
- 双足支撑。
- 单腿支撑。
- 高动作变化率。
- 高关节速度。

不要只使用 WM Training Loss 评价预测准确度。

### 3. Imagined Reward 与真实 Reward

从相同真实状态开始：

- 使用冻结 Policy。
- 在 Newton 中执行真实 Rollout。
- 在 WM 中执行 Imagined Rollout。
- 尽可能对齐动作与外部目标时钟。

比较短时预测回报和对应的状态误差，避免把不同轨迹分布的累计回报直接相减解释为模型偏差。

重点判断：

**Actor 是否在 WM 想象中学会提高奖励，但真实 Newton 中对应的 Footstep Tracking 没有改善？**

如果发现显著误差，进一步检查 WM 的局部动作梯度是否可信。

## 七、任务五：最小范围的训练修复实验

仅在完成前四部分后，根据证据选择最多两个最有价值的修复方向。

候选方向包括：

1. 调整 Reward，使 Foot Tracking / Touchdown 与 Survival 不再产生明显的错误激励。
2. 修复错误的 Touchdown 或 Termination 逻辑。
3. 改善 Critic 价值估计与 Bootstrap。
4. 降低 Actor 更新造成的动作分布迁移，例如调整 Actor 学习率、更新频率或增加可信动作分布约束。
5. 增强 WM 对当前 Actor 动作区域的数据覆盖。
6. 对超出机械限位的原始 PD Target 增加可微软惩罚。

**不要同时修改多个未经过验证的超参数。**

优先使用短训练消融，每组建议 100–300 iterations，训练预算可根据实际速度调整，但不允许自动启动完整 5000 iterations。

使用不同输出目录，保留现有 M4.2 v2 全部模型和日志。

禁止：

- 更换为 Full-body Actor。
- 修改 F2 Reference。
- 更换机器人模型。
- 修改 Newton 物理参数。
- 直接改 Action Scale 0.35。
- 取消现有 EPA 安全隔离。
- 为了提高存活率而牺牲 Foot Tracking 目标。

需要先证明是哪一个机制导致优化方向错误，再实施对应修复。
