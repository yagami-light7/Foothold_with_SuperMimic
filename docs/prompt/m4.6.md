# M4.6 — Upper-body Motion Prior Weight Ablation

## 任务目标

准备 M4.6 上半身运动先验权重消融实验。

当前已有两组完整 Fresh Start 基线：

- **M4.3**：`body_prior_weight=0.00`，5000 iterations，F2 四步跟踪成功，具有较好的初态扰动鲁棒性。
- **M4.5**：`body_prior_weight=0.10`，5000 iterations，上半身跟踪改善，但完整步态与扰动鲁棒性退化。

M4.5.1 的 Fine-tuning 消融由于 Critic、Optimizer、Replay 等状态重建产生明显训练干扰，无法用于判断不同先验权重的优劣。

因此，本次不再采用 Fine-tuning，改为从随机初始化进行两组标准训练：

| 实验   | Body Prior Weight | 训练方式    | Iterations |
| ------ | ----------------: | ----------- | ---------: |
| M4.6-A |              0.02 | Fresh Start |       5000 |
| M4.6-B |              0.05 | Fresh Start |       5000 |

与已有的 M4.3（0.00）及 M4.5（0.10）构成完整的权重消融。

**本次任务只需要准备好训练环境、配置和一键启动脚本，不要实际启动正式训练。训练完成后，我会另行要求生成实验报告。**

## 一、严格继承 M4.3 训练配置

以 `configs/roban/m4_3.json` 为唯一配置基线。

检查仓库实际文件路径与配置解析逻辑。

两组实验必须保持：

- Roban 21-DoF。
- 原始 F2 Reference，261 帧，50 Hz，5.2 s。
- Isaac Lab 3.0 + Newton/MJWarp。
- 物理子步：8 × 2.5 ms。
- Actor：原始 `10×69 + 320 → 21`。
- Critic：原始 970D 特权观测。
- 原始 World Model 网络。
- WM Window = 4。
- BPTT Horizon = 16。
- Environments = 256。
- Iterations = 5000。
- Seed = 0。
- WM-only Warmup = 1000 iterations。
- Actor LR = `2e-4`。
- 原始 WM/Critic LR 与优化配置。
- Action Scale = `0.35 × effort_limit / Kp`。
- **Hard Clamp Action Mapping**。
- M4.3 Swing-Aware Reward 全部保留。
- 原 Replay、Normalization、Termination、Touchdown 判定及 Newton 物理保护。

唯一实验变量：

```text
body_prior_weight
```

对应两个值：

```text
M4.6-A: 0.02
M4.6-B: 0.05
```

不修改 Body Prior 的公式、Quality Gate、Arm/Waist 权重比例或 Reference。

不调整学习率、Reward 其他权重、PD 参数、Action Mapping、网络结构及训练更新频率。

如现有代码会依据 Reward 配置自动更新回报归一化上界，应沿用原有规则。不要额外手动修改 Critic Bootstrap 或其他配置。

## 三、训练前检查

在不启动正式训练的前提下完成以下验证。

### 3.1 配置与初始化检查

确认：

- 两组配置均可被训练入口正确解析。
- Actor/WM/Critic 维度与 M4.3 完全一致。
- Body Prior 奖励能够正常计算和反向传播。
- Reward 无 NaN/Inf。
- WM、Actor、Critic 梯度有限。
- Hard Clamp 生效。
- F2 文件路径正确。
- 不存在跨实验 Checkpoint 继承。
- 两组在 Seed 0 下生成一致的初始模型参数。

如果可以，比较新实验初始化模型与历史 M4.3 的 Initial Checkpoint，并记录参数指纹；同时确认两组的奖励权重确实不同。

### 3.2 短 Smoke Test

允许进行极短的 Smoke Test，用于验证：

- Isaac Lab + Newton 能够初始化。
- Reward 正常计算。
- WM 与 BPTT 可以完成一次正常优化。
- Replay 和 Checkpoint 正常工作。
- 不出现 CUDA、EPA、NaN、Inf 等严重问题。

Smoke Test 必须使用独立临时输出目录，不能占用正式实验目录。

测试通过后删除或隔离临时数据。

**不能将 Smoke Test 算作正式训练，不得提前运行完整的 5000 iterations。**

## 四、创建一键训练脚本

创建一个训练脚本，例如：

```text
tools/run_m46_ablation.sh
```

脚本需要完成以下工作：

### 4.1 自动启动两组实验

只需执行一次命令，依次完成：

```text
M4.6-A: body_prior=0.02, 5000 iterations
                  ↓
M4.6-B: body_prior=0.05, 5000 iterations
```

两组必须串行运行，不能在同一块 GPU 上同时启动。

### 4.2 使用 tmux

要求：

- 由脚本自动创建 tmux Session。
- 用户关闭终端或 SSH 断线不影响训练。
- 训练日志实时写入文件。
- 能够重新连接 tmux 查看训练过程。
- 训练完成后保留日志和 Checkpoint。
- 正确记录每组退出码。

如现有 Docker/容器启动脚本需要在宿主机启动 tmux，应采用与项目现有 `tools/run_roban.sh` 相兼容的方式，确保 tmux 保护的是实际训练进程，而不只是一个很快退出的外层命令。

### 4.3 输出目录

使用：

```text
outputs/m4_6/
├── w002/
│   ├── checkpoints/
│   ├── logs/
│   └── config/
└── w005/
    ├── checkpoints/
    ├── logs/
    └── config/
```

保持 M4.3、M4.4、M4.5、M4.5.1 的所有实验文件不变。

### 4.4 Checkpoint

沿用 M4.3 的保存机制。

至少保存：

- Initial。
- Iter 1000。
- Iter 2000。
- Iter 3000。
- Iter 3500。
- Iter 4000。
- Iter 4500。
- Iter 5000。
- Best。
- Last。

每 500 iterations 保留可恢复 Checkpoint。

Checkpoint 应包含已有机制支持的网络参数、Optimizer、Normalization、训练轮次及 RNG 状态。

Best 仍以完整四步成功率和有效 Touchdown 为最高优先级，而不是单纯依赖 Foot RMSE 或 Reward。

保留 M4.3 现有的轻量周期评估，避免新增耗时很大的独立评估任务。

正式的多种子鲁棒性评估留到训练完成后的 Report 阶段。

### 4.5 失败保护与恢复

训练脚本必须满足：

- 第一组成功结束后自动启动第二组。
- 第一组失败则停止，不得静默启动第二组。
- 不得覆盖已有的正式 Checkpoint。
- 若训练意外中断，记录失败原因与最后有效检查点。
- 提供安全恢复机制，避免用户重新运行脚本时意外覆盖历史训练。
- 正式新训练与 Resume 必须有明确区分。
- 保留现有 Newton EPA、Invalid Transition、Fatal 异常保护。

不允许通过关闭物理安全保护来完成实验。
