# M4.11 — Upper-body Cartesian Tracking with Hand Position Huber

## 1. 实验背景

首先阅读 `m4.10_report.md`、M4.10 Reward 实现、训练配置、独立 CUDA Newton Evaluation 和上半身运动质量评价代码。

M4.10-C9000 已经实现较好的足部跟踪、Root Tracking、上半身姿态及运动平滑性。

但通过可视化发现，双臂仍然存在向身体内侧收拢、异常屈肘及摆臂不协调等现象。

当前 Joint Space Posture Tracking 已经显著改善肩肘关节姿态，但多个关节的角度误差仍然可能通过运动链累积，导致手部空间位置存在较大偏差。

因此，本轮引入 Cartesian Space Hand Position Tracking，与现有 Joint Space Huber Prior 形成互补。

---

## 2. 核心目标

在保持 C9000 已有运动能力的基础上：

1. 降低双手相对于躯干的空间位置误差。
2. 减少双手向身体中央异常收拢的现象。
3. 改善上臂伸展方向和前臂空间姿态。
4. 改善摆臂幅度及其与步态的协调性。
5. 保持精准足部跟踪。
6. 保持 Root Tracking 和运动平滑性。
7. 不显著降低初始状态偏差恢复能力。

本轮只新增 Hand Position Huber。

不新增 Elbow Position Tracking、Hand Velocity Tracking、Hand Orientation Tracking 或其他奖励。

## 3. Hand Position Huber Reward

### 3.1 躯干局部坐标系

采用 Torso Local Frame，而不是世界坐标系中的手部位置。

对于左右手：

\[
p*i^{local}
=
R*{torso}^{T}
(p*i^{world}-p*{torso}^{world})
\]

Reference 同样使用其自身躯干位姿：

\[
p*i^{ref,local}
=
(R*{torso}^{ref})^T
(p*i^{ref,world}-p*{torso}^{ref,world})
\]

其中：

\[
i\in\{L,R\}
\]

这样可以避免机器人整体平移、转向或合理躯干倾斜产生额外的手部跟踪惩罚。

必须核对 M4.10 手部局部 RMSE 的实际实现，优先复用相同的：

- Torso Link。
- 左右手 Link。
- 手部关键点位置与固定偏置。
- 坐标轴定义。
- Quaternion 顺序。
- 关节名称与索引映射。

不得未经验证直接使用腕关节原点替代历史评价中的手部关键点。

Roban 没有独立手部控制自由度时，使用现有肩肘关节运动学链计算手部关键点位置。

### 3.2 姿态误差

分别计算左右手位置误差：

\[
e_i=
\|p_i^{local}-p_i^{ref,local}\|\_2
\]

采用 Dead-zone：

\[
d*i=\max(e_i-\delta*{hand},0)
\]

归一化：

\[
x*i=\frac{d_i}{\sigma*{hand}}
\]

Huber 函数：

\[
H(x)=
\begin{cases}
\frac12x^2,&0\leq x\leq1\\
x-\frac12,&x>1
\end{cases}
\]

最终奖励：

\[
r*{hand}
=
-\Delta t\,w*{hand}Q_t
\frac{H(x_L)+H(x_R)}{2}
\]

其中 Q 为现有 Reference Quality Gate。

### 3.3 固定参数

| 参数                 |              数值 |
| -------------------- | ----------------: |
| Hand Position Weight |              0.10 |
| Dead-zone            |            0.03 m |
| Huber Sigma          |            0.10 m |
| Control dt           |            0.02 s |
| 左右手权重           |         0.5 / 0.5 |
| 坐标系               | Torso Local Frame |

设计原则：

- 手部误差在 30 mm 以内不惩罚。
- 超出范围后提供连续的恢复梯度。
- 大误差区域避免指数奖励饱和。
- 保留一定的主动平衡自由度。
- 左右手独立计算 Huber，再取平均。
- Quality Gate、Weight 和 dt 均只乘一次。

以上参数作为统一配置，不开展离线超参数网格搜索，也不针对单条 Reference 重新标定。

如果当前 Reward 框架已经在外层统一乘 dt 或 Weight，则新增函数只返回对应的未加权项，避免重复计算。

## 5. 可微运动学与 BPTT

首先检查现有 `RobotKinematics` 是否已经能够计算可微的：

- Torso Position / Orientation。
- Left Hand Position。
- Right Hand Position。

如果已有实现，优先复用。

如果尚未支持手部关键点，则在现有可微 FK 框架中扩展相应运动链。

不需要重新引入一个独立的大型运动学框架。

新增奖励的梯度路径应为：

```text
Actor
  ↓
Raw Action
  ↓
Action Mapping
  ↓
Effective Action
  ↓
World Model
  ↓
Predicted Joint / Root State
  ↓
Differentiable Forward Kinematics
  ↓
Torso-local Hand Positions
  ↓
Hand Position Huber
  ↓
Actor BPTT Gradient
```

Reference 手部目标作为固定任务数据，不需要反向传播。

必须确保：

- FK 不使用破坏梯度的 `.detach()`、NumPy 或 CPU 转换。
- 不使用 PD Target 代替实际或 WM 预测的关节状态。
- 不使用不可微的 MuJoCo FK 作为 BPTT 主路径。
- Reference 与预测状态使用同一个步后时间索引。
- Newton Real Reward 与 Imagined Reward 使用相同数学定义。
- 新增奖励在超出容许范围时能够对对应肩肘动作产生有效恢复梯度。

由于手部局部坐标同时涉及躯干和上肢运动学，应检查腰部及肩肘梯度是否符合预期，不要求所有关节始终具有非零梯度。

## 7. Critic 与 Replay 适应

新增 Hand Position Huber 后，Critic 所对应的长期回报定义发生变化。

不能未经处理直接恢复旧 Reward 的完整训练状态。

### 7.1 Checkpoint 检查

首先确认 C9000 Checkpoint 中实际保存了哪些内容：

- Actor 参数。
- WM 参数。
- Critic 参数。
- Normalization Buffers。
- Optimizer State。
- Replay Buffer。
- LR Scheduler。

如果部分状态没有保存，明确记录，不假设可以完整 Resume。

### 7.2 共同初始化

建议两组均：

- 加载 C9000 的 Actor、WM、Critic 及归一化器。
- 重新初始化 Optimizer。
- 使用相同方式建立新 Replay。
- 不直接沿用已经缓存的旧 Reward 和旧 Value Target。

优先采用 C9000 冻结 Actor 采集的新 Replay，使两组具有可比较的初始状态分布。

对于同一批采集数据，分别按照 A/B 的 Reward 重新计分。

### 7.3 Critic Warm-up

正式 Actor 微调前，增加共同的 200 iterations Critic Warm-up 阶段。

两组均：

- 冻结 Actor。
- 暂时冻结 WM。
- 按各自 Reward 更新 Critic。
- 使用相同的采集和更新预算。
- 检查 Value Target、Critic Loss 和 Bootstrap 梯度。

Warm-up 完成后恢复 M4.10 的 WM、Actor、Critic 联合训练，共 2000 iterations。

Warm-up 与正式微调轮次分开统计。

如果实际代码不支持上述训练阶段，需要先实现最小隔离机制，或者提出数学与实验口径一致的替代方案，并说明原因。

不得只为 B 组增加额外训练预算而忽略 A 组的对照公平性。

### 7.4 训练后期稳定性

M4.10-C10000 曾出现：

- WM 预测误差增大。
- Critic Loss 增大。
- Real/Imagined Reward 差异扩大。
- Foot Tracking 退化。
- 上身高频抖动增加。

因此，本轮必须监控上述指标。

特别关注 Critic Bootstrap 梯度相对于 Foot、Root、Joint Huber 和 Hand Huber 的强度。

暂时不修改 Critic Bootstrap 权重或 BPTT 目标，避免引入额外实验变量。

## 8. 训练前检查

### 8.1 FK 数值一致性

使用原始 F2 和 C9000 已有真实轨迹，对照：

- MuJoCo 独立 FK。
- 现有可微 FK。
- M4.10 手部位置评价实现。

检查左右手、躯干位置及局部坐标变换一致性。

增加整体刚体变换不变性测试：

同时对机器人 Root 施加相同的平移和旋转，Torso-local Hand Position 应保持不变。

### 8.2 Reward 单元测试

至少验证：

1. 手部完全匹配 Reference 时惩罚为零。
2. 手部误差位于 30 mm 容许范围内时惩罚为零。
3. 超出范围后惩罚随误差单调增加。
4. Huber 分段边界一阶导数连续。
5. 左右手正确对应。
6. Reference Quality Gate 正确。
7. Weight 和 dt 没有重复计算。
8. 手部位置和关节梯度有限。
9. Hand Weight 为零时与 M4.10-C 保持一致。
10. Real Reward 与 Replay Reward 重算一致。

### 8.3 历史轨迹重新计分

使用：

- M4.8-C Best。
- M4.9-C9500。
- M4.10-A10000。
- M4.10-B8000。
- M4.10-C9000。
- M4.10-C10000。

统计新增 Hand Huber 的：

- 每步平均贡献。
- P95/Max 惩罚。
- 左右手位置误差。
- 容许范围外比例。
- 不同步态阶段的奖励分布。

确认该奖励能够识别异常手部姿态。

只进行数学及实现正确性检查，不进行大规模奖励权重搜索。

### 8.4 BPTT 梯度审计

分别统计：

- Foot Tracking。
- Root Tracking。
- Joint Huber。
- Hand Huber。
- Smoothness。
- Critic Bootstrap。
- 总 Actor Gradient。

检查各项梯度范数及余弦相似度。

重点验证新增 Hand Huber 是否主要提供合理的上肢姿态纠正信号，以及是否与足部任务产生明显竞争。

如果发现明显实现错误，先修复再开展训练。

如果固定参数本身导致严重数值问题，报告证据，不静默修改正式权重。

6. 手部位置误差随步态相位的变化。
7. 上身速度、加速度和 Jerk。
8. 正常及初始状态存在偏差的成功、失败视频。

重点观察：

- 双手是否仍然集中在腰腹附近。
- 双臂是否能够自然下垂并适度摆动。
- 前臂是否出现异常向内旋转或过度屈曲。
- 是否存在明显横向伸展。
- 上肢姿态改善后是否影响动态平衡。

Hand Position Huber 只直接约束空间位置，不保证手部朝向一定正确。残余姿态问题应在报告中单独说明。
