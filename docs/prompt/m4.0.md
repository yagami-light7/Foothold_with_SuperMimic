# M4.0 — SuperMimic + Roban F2 Reference Tracking Pilot

## 0. 任务目标

我们已完成 M3.7.1 Motion Reference Generator，现在希望在本地 RTX 4060 8GB 上，进行一次小规模 SuperMimic Motion Tracking 训练实验。

本次只使用一条 Reference：

**M3.7.1 / F2 — Forward Walking**

其参数为：

- Robot：Roban，21 Actuated DoF + 6 Floating-base DoF
- Source Clip：`forward_012`
- Step Length：0.17 m
- Step Frequency：1.0 Hz（交替落脚事件频率）
- Yaw Rate：0
- Duration：5.2 s
- Frames：261
- Reference FPS：50 Hz

原始 Reference 在 Generator 仓库中的相对路径：

`outputs/m3_7_1/forward/F2/reference.npz`

该 Reference 已通过运动学、SQP 与关节限位检查，但完整逆动力学可行性不足。因此，本次需要验证真实闭环跟踪表现，不应假定 Reference 本身动力学完全可行。

**核心目标：验证 SuperMimic Policy 能否通过反馈控制，在 Newton/MJWarp 中稳定跟踪 F2，完成基本的平地向前行走。**

本次不实现 Online Generator，不进行多步态训练，也不重新修改 Motion Reference。

## 1. 首先审查现有 SuperMimic 仓库

请先检查当前仓库：

1. 当前机器人是否为 Roban，还是原来的 KUAVO S54 / G1。
2. Robot MJCF / URDF、关节数量和顺序。
3. Isaac Lab 3.0 + Newton/MJWarp 环境是否已经接入。
4. SuperMimic 网络结构、训练入口和 Checkpoint 管理。
5. Motion Reference 读取格式。
6. Reward、Observation、Action、Termination 和 Reset 设计。
7. 是否存在可复用且机器人模型完全兼容的预训练 Checkpoint。

**特别注意：Roban 与 S54 的 DoF 和机器人结构不同，禁止直接复用不兼容的网络参数、关节索引和 PD 配置。**

如果仓库当前仅支持 S54，请先评估 Roban 适配需要修改的最小模块。

优先使用独立 Task / Robot Config 接入 Roban，不要破坏原有 S54 训练任务。

如果缺少必要模型或资源，明确说明阻塞项，不能使用 S54 模型冒充 Roban 进行实验。

## 2. F2 Reference 导入

检查 Generator 仓库是否可以访问 F2 NPZ。

如果无法直接访问，提供明确的数据拷贝或软链接方案，不要假设两个仓库位于同一目录。

编写最小 Reference Adapter，正确读取：

- Root Position / Quaternion。
- Actuated Joint Positions。
- Foot Position / Orientation。
- Contact Schedule。
- Reference Time。
- Motion Duration。
- Joint Names。
- Validity Masks。

重点检查：

- 世界坐标系和 Root Frame。
- Quaternion 顺序（wxyz / xyzw）。
- 21 DoF 关节名称与索引。
- Foot Sole 和 Foot Link 的区别。
- Reference 与 Simulation 的采样间隔。
- 初始机器人状态。
- Reference 是否存在非连续首尾帧。

使用时间插值获取任意仿真时刻的 Reference。

不要简单假设仿真频率永远等于 50 Hz。

**不要直接无限循环播放 5.2 s 的 Reference，除非验证首尾位姿、速度和接触相位能够连续衔接。**

第一版可以在 Reference 结束时终止 Episode，并记录是否成功完成动作。

## 3. Newton 环境验证

正式训练前，先完成最小环境测试。

要求：

- Isaac Lab 3.0。
- Newton/MJWarp。
- Roban 原始模型。
- 平地。
- 关闭非必要渲染。
- 支持 Headless 运行。

验证以下内容：

1. 机器人可以正常生成和 Reset。
2. Root 和关节状态没有 NaN/Inf。
3. 关节顺序与 Reference 完全一致。
4. PD Controller 的输出和力矩限制合理。
5. Action Dimension 正确。
6. Foot Contact 状态可正常读取。
7. Episode Reset 不会产生状态跳变。
8. Isaac Lab 与 World Model 的时间步长配置一致或具有明确的时间映射。

优先进行单环境和小规模并行环境 Smoke Test。

不要直接启动正式长时间训练。

- World Model 如何采样并训练。

如果一条 5.2 s Reference 不足以支持当前训练流程，应明确说明，并保持实验目标为训练流程及基础跟踪可行性验证，不得宣称已完成泛化步态学习。

## 5. Observation 与 Motion Goal

优先沿用现有网络接口，避免进行大规模架构修改。

Policy 可以使用：

### Proprioception

- Root Angular Velocity。
- Projected Gravity。
- Joint Position。
- Joint Velocity。
- Previous Action。
- 必要的历史观测。

### Motion Goal

采用现有 SuperMimic Goal Encoder 接口。

从 F2 Reference 中提供：

- Future Root Motion。
- Future Foot Targets。
- Gait Phase / Contact Schedule。
- 必要的 Future Joint Motion。

如果原网络没有直接支持 Foot Goal 或 Contact Phase，应先评估最小兼容修改，而不是重新设计网络。

对不同量纲进行合理归一化。

避免将仿真中无法实际获得的未来真实机器人状态作为 Actor 输入。

## 6. Reward 设计

第一版不要设计复杂的新 Reward System。

复用现有 SuperMimic Motion Tracking Reward，重点检查以下目标：

**高优先级**

- Robot Survival / Upright。
- Root Orientation。
- Foot Tracking。
- 期望前进运动。

**中优先级**

- Root Height Tracking。
- Joint Motion Prior Tracking。
- Contact Consistency。

**正则项**

- Action Rate。
- Joint Velocity。
- Joint Acceleration（如已有）。
- Excessive Torque。

特别注意：

M3.7.1 的 Reference 尚未达到连续逆动力学可行，因此不要要求 Policy 严格跟踪每个关节。

应允许 Policy 为保持稳定性，对 Reference 做必要的关节和 Root 偏离。

建议进行两种 Reward 配置：

- A：现有 Motion Tracking Reward。
- B：适度增强 Foot / Root Tracking，降低严格关节模仿权重。

先跑 A 的 Smoke Test，再根据结果决定是否运行 B。

不要一次性进行大量 Reward 网格搜索。

## 7. 本地 RTX 4060 训练配置

硬件：RTX 4060，8GB VRAM。

优先使用保守配置：

- 初始 `num_envs`：128 或 256。
- 后续根据实测显存和 FPS 调整。
- 不强制使用服务器上的 1024/2048 环境配置。
- 不加载不必要的 GUI 和视频渲染。
- 控制 World Model Batch、BPTT Horizon 和 Replay Buffer 显存。

训练分为：

### Stage A — Environment Smoke Test

少量环境、少量迭代。

验证 Reference、Observation、Action、Reward、World Model、Backward 和 Checkpoint 的完整链路。

### Stage B — Short Training Pilot

在显存允许的情况下运行一段小规模训练。

记录：

- Training FPS。
- GPU Memory。
- World Model Loss。
- Actor / Critic Loss。
- Normalized Return。
- Episode Length。
- Survival Rate。
- Foot Tracking Error。
- Root Tracking Error。

训练入口应支持运行时长或迭代数预算，提供可中断和恢复机制。

不要为追求训练速度牺牲数值稳定性。

## 8. 独立 Evaluation

必须区分训练回报与真实仿真表现。

评估时关闭探索噪声。

重点检查：

1. 能否稳定站立。
2. 能否完成第一次摆动和落脚。
3. 能否连续完成四次计划落脚。
4. 能否走完整段 5.2 s Reference。
5. 实际 Root XY 位移。
6. Foot Position RMSE。
7. Root Position / Orientation Error。
8. 是否发生提前跌倒。
9. 实际接触与计划接触是否一致。

每个候选 Checkpoint 至少进行若干次独立 Reset 评估，并汇总成功率，不只展示单条成功视频。

训练时可使用 Curriculum，但第一版优先验证完整 Reference 从起始状态播放的可行性。

如果训练不稳定，应首先区分：

- Reference 本身难度。
- Robot / PD 配置错误。
- Motion Goal 输入错误。
- World Model 预测误差。
- Reward 权重冲突。
- Policy 优化不足。

不得直接把所有失败归因于训练时间不够。
