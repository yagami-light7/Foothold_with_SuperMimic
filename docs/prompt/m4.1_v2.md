# M4.1 — Roban SuperMimic / Newton-MJWarp 动力学异常诊断与稳定性修复

## 0. 任务背景与核心目标

当前 Roban SuperMimic M4.1 已完成以下改动：

1. Actor 输出 21 维归一化动作，通过关节活动范围中点映射为 PD Position Target。
2. Critic 启用了完整全身 Motion Reference，采用非对称 Actor–Critic。
3. Isaac Lab 3.0 + Newton/MJWarp 执行仿真。
4. 使用 M3.7.1 F2 Motion Reference 训练。
5. 本地 RTX 4060 8GB 进行强化学习。

然而，训练至约 1140 iterations、累计 761164 条真实转移时，出现严重的关节状态异常并触发 `FloatingPointError`。

典型日志：

**异常 A：腿部关节越界**

- Joint：`leg_r1_joint`
- Joint Limit：[-2.443, 3.228] rad
- q_before：-1.330 rad
- q_after：-3.251 rad
- PD Target：-2.257 rad
- Joint Velocity：-74.41 rad/s
- 末子步 nefc：1/1024

**异常 B：手臂关节状态爆炸**

- Joint：`zarm_r2_joint`
- Joint Limit：[-3.316, 0.520] rad
- q_before：-0.602 rad
- q_after：-13.37 rad
- PD Target：-0.4652 rad
- Joint Velocity：-2378 rad/s
- Root Linear Velocity：59.58 m/s
- Root Angular Velocity：634.4 rad/s
- `state_finite=True`
- `overflow=NONE`
- `nefc=41/1024`

异常抛出位置：

- `supermimic/integration/m4_task.py::validate_physics_step`
- `supermimic/env.py::step`
- `supermimic/train.py::collect`

**核心问题：Actor 的 PD Target 处于合法关节范围内，但 Newton/MJWarp 积分后的真实关节状态却产生极端越界和不合理速度。**

请实际排查并修复这一问题，而不是简单屏蔽异常或让训练继续跳过错误。

## 1. 必须保留的设计

### 1.1 保留统一 Action Mapping

我们的最终目标是让不同 Motion Reference 共享一个通用的 Footstep-conditioned Policy。

因此，必须保留：

\[
a_t\in[-1,1]^{21}
\]

\[
q_{\mathrm{mid},j}=\frac{q_{\min,j}+q_{\max,j}}{2}
\]

\[
\alpha_j=\frac{q_{\max,j}-q_{\min,j}}{2}
\]

\[
q_{\mathrm{target},j}=q_{\mathrm{mid},j}+\alpha_j a_{t,j}
\]

要求：

- 不恢复以前的 Default-centered Mapping。
- 不把 F2 Reference 关节轨迹作为动态 Action Center。
- 不直接缩小完整关节目标的可表达范围。
- 不引入新的 Motion Reference Generator。
- 不修改 Actor 输入、Critic 输入和 SuperMimic 主体网络。
- 不通过降低 Reward、增加课程学习等方式掩盖物理异常。

允许根据诊断结果调整 PD、Actuator、物理仿真参数和必要的控制安全机制。

如果需要引入关节目标变化率限制，应将其作为独立、可配置、可关闭的控制滤波器，保留原始归一化动作和完整关节范围映射，并明确说明其影响。不得悄悄改变上述 Mapping。

### 1.2 保留原始训练范式

保持：

- Motion Encoder + Shared Decoder。
- World Model。
- BPTT。
- Asymmetric Actor–Critic。
- Actor：本体历史 + Future Foot/Root Goals。
- Critic：完整机器人状态 + Privileged Context + 完整未来 Motion Reference。

本轮优先修复物理仿真，不要重新设计训练算法。

## 2. 第一阶段：检查完整控制链路

首先阅读并检查：

- `supermimic/env.py`
- `supermimic/roban.py`
- `supermimic/robot.py`
- `supermimic/integration/m4_task.py`
- `supermimic/roban_runtime.py`
- `supermimic/train.py`
- Roban MJCF、URDF、USD
- 当前 M4.1 Config
- Newton/MJWarp 初始化和物理配置

以实际代码为准，不要假设文件结构或接口一定与 M4.0 相同。

需要明确整个控制链路：

`Policy Raw Output → tanh / Exploration Noise → Action Bound → Joint Mapping → PD Controller → Torque Limit → Newton/MJWarp → Joint State`

逐项核实：

1. Actor 输出是否真的限制在 [-1,1]。
2. 探索噪声施加在 `tanh` 之前还是之后。
3. 是否存在重复缩放、重复裁剪或错误的关节顺序。
4. 21 个关节的位置上下限是否来自正确的 Roban 模型。
5. 每个关节的 PD Target 是否始终处于真实位置限位内。
6. Actual Action、PD Target、Applied Torque 是否存在单位或索引错误。
7. 真实 Rollout、WM Imagined Rollout、Replay、Evaluation 是否使用一致的 Action Mapping。
8. Actor 是否在起步阶段频繁输出接近 ±1 的极端动作。

增加轻量诊断，记录：

- Raw Action 的均值、标准差、最大值。
- Action 接近 ±1 的比例。
- PD Target 的单步变化量。
- 每个关节的 Position Error。
- PD 比例项和阻尼项。
- 理论力矩、实际提交力矩及力矩饱和比例。
- 实测关节位置、速度和加速度。

**重点判断：Action Mapping 生成了激进但合法的目标，还是控制链路内部存在实际实现错误。**

## 3. 第二阶段：深入检查 PD / Actuator 配置

请不要只关注 Action Mapping，必须把 PD 和机器人动力学联合分析。

### 3.1 审查实际 PD 实现

确认当前使用的是：

- Explicit PD / Torque Control；
- Newton Native Actuator；
- 还是 Solver-side Implicit Drive。

明确实际控制公式、执行频率、执行位置，以及控制量在 Newton 中的提交方式。

检查是否存在：

- 上层 PD 和底层隐式 Drive 同时生效。
- Stiffness / Damping 被重复应用。
- Effort Limit 仅用于日志而未实际生效。
- Explicit PD 的力矩在每个子步和每个控制步的更新方式不正确。
- Actuator Torque Limit、Joint Effort Limit 配置不一致。
- Actuator 数据与 Newton 真实求解器数据不一致。

不要仅凭配置文件中的 `Kp`、`Kd` 或 `effort_limit` 判断真实控制行为。

### 3.2 分析 PD 动态响应

检查当前各关节：

- Kp。
- Kd。
- Effort Limit。
- Armature。
- Joint Damping。
- Friction。
- 关节等效惯量。
- 物理积分时间步长。

特别关注：

- `leg_r1_joint`
- `leg_r3_joint`
- `zarm_r2_joint`

排查是否存在高 Kp、低阻尼、低惯量和大目标阶跃共同造成的数值失稳。

进行可复现的单关节或固定基座 PD Step Response 测试：

1. 小幅阶跃。
2. 中等阶跃。
3. 接近关节边界的目标。
4. 高速状态下的制动。

记录响应时间、超调、速度峰值、实际力矩及稳定性。

如果需要调整 Kp/Kd，请采用有依据的、逐关节或分关节组的配置，不要简单将所有 PD Gain 乘以任意系数。

确保调整后仍具有完成 F2 摆腿和支撑动作所需的控制能力。

## 4. 第三阶段：重点排查 Newton/MJWarp

这是本轮最重要的任务。

当前异常不是 NaN，而是有限数值下的非物理速度和关节越界。

请检查所安装 Newton、Isaac Lab、MJWarp 的实际版本和代码路径。

优先参考与本地安装版本匹配的官方文档：

- https://isaac-sim.github.io/IsaacLab/v3.0.0/source/how-to/prepare_asset_for_newton.html
- https://isaac-sim.github.io/IsaacLab/v3.0.0/source/how-to/solver_tuning_mjwarp.html
- https://newton-physics.github.io/newton/latest/solvers/mujoco.html
- https://docs.nvidia.com/isaaclab/3.0/concepts/actuators

注意 API 和参数名称可能随版本变化，必须以本地实现为准。

### 4.1 Joint Limit

检查 Roban 模型经过 MJCF → USD → Newton 转换后：

- Joint Type 是否正确。
- Joint Axis 是否正确。
- Joint Range 是否正确。
- Position Limit 是否实际启用。
- Limit Stiffness / Damping 是否合理。
- MuJoCo `solreflimit` / `solimplimit` 是否正确导入。
- Newton 运行时实际 Joint Limit 与 MJCF 是否一致。
- 约束求解器是否正确生成关节限位约束。

重点回答：

**为什么 `leg_r1_joint` 能超过下限约 0.8 rad，`zarm_r2_joint` 能超过下限约 10 rad？**

区分正常的软限位穿透和数值求解失稳。

不要把直接裁剪仿真状态中的 `qpos` 当作默认解决方案。

### 4.2 Velocity Limit

特别注意：

MJWarp 不一定会在物理积分过程中强制执行配置的 `joint_velocity_limit`。

请核实本地版本中：

- `actuator_velocity_limit`
- `joint_velocity_limit`
- 当前异常检测中的 `speed_limit`

分别由谁使用、在哪个阶段生效。

如果这些限制仅用于诊断或终止，不能错误地将其当作真正的求解器速度约束。

### 4.3 Contact / Collision

检查：

- 双足碰撞几何。
- Foot Sole 与 Collision Geometry 偏置。
- 初始 Reset 是否存在穿透。
- 自碰撞过滤。
- 地面摩擦和碰撞参数。
- 接触冲量及接触约束收敛。
- 是否存在碰撞对的错误配置。
- 质量、惯量、CoM 和几何单位。

重点观察异常发生前几个物理子步的接触状态。

不要将 `nefc=1/1024` 简单判定为 Overflow。

需要分别记录：

- 实际 Contact Count。
- Constraint Count。
- `nconmax`、`njmax`。
- Newton/MJWarp Overflow Flags。
- Solver Iteration、收敛信息和约束残差（若可获取）。

当前日志 `overflow=NONE`，所以不能在没有证据的情况下把问题归咎于约束缓冲区容量不足。

### 4.4 Timestep / Substeps / Solver Parameters

当前控制周期预计为 20 ms，每控制步包含 4 个 5 ms 的物理子步，请核对实际配置。

在固定初始状态和相同 Action Sequence 下对比：

- 原始物理子步数。
- 物理子步加倍。
- 必要时适度提高求解器迭代次数。

保持 Policy 控制周期不变，单独比较物理积分精度。

记录：

- 关节位置越界。
- 最大关节速度。
- Root 速度。
- 接触稳定性。
- Solver 收敛。
- FPS 和运行开销。

**不要一开始就同时修改 PD、dt、Solver Iterations 和接触参数，否则无法定位根本原因。**

## 5. 第四阶段：构造可复现的最小异常案例

不要依赖随机运行上千 iterations 才发现问题。

请构建可重复的 Newton 诊断脚本，支持保存：

- Robot State。
- Actor Action。
- PD Target。
- 实际提交力矩。
- 环境随机种子。
- F2 Reference Frame。
- 接触与 Solver Diagnostics。
- 异常前若干个控制步的数据。

优先尝试复现已报告的异常环境。

如果无法直接恢复历史异常状态，则在新的训练或 Rollout 中建立 Ring Buffer，在触发异常时自动导出完整诊断快照。

至少完成以下实验：

| 实验 | Action | 目的 |
|---|---|---|
| A | 归一化零动作 | 检查默认关节中点目标 |
| B | 固定 F2 初始关节目标 | 隔离 Actor，检查 PD 和动力学 |
| C | 固定的小幅随机动作 | 检查基本控制稳定性 |
| D | 完整范围随机动作 | 检查大目标变化与饱和 |
| E | 保存的 M4.1 Actor 动作 | 复现实际训练中的状态异常 |

特别注意：

零动作不等于稳定站立，机器人正常失去平衡或跌倒本身不是求解器错误。

重点检测的是非物理关节跳变、极端速度、异常能量增长和严重的限位穿透。

如果能够复现异常，进一步区分：

- 没有接触也发生异常：优先检查关节、Actuator 和积分。
- 接触发生后才异常：优先检查碰撞、接触和约束求解。
- 只有较大 Action 才异常：优先检查目标阶跃、PD 饱和和积分稳定性。
- 只在大量并行环境中异常：检查环境隔离、索引、GPU Buffer 和求解器容量。

如现有环境具备可用的原生 MuJoCo CPU 对照条件，可用相同 Roban MJCF、状态及控制输入进行辅助比较，但不要求额外迁移整套训练系统。

## 6. 第五阶段：根据证据实施最小修复

完成定位后，允许修改：

1. 错误的 Joint / Actuator 参数映射。
2. PD Gain、Damping 或合理的 Armature。
3. Effort Limit 的实际执行路径。
4. Joint Limit Solver 参数。
5. Contact / Collision 配置。
6. Physics dt、Substeps 或 Solver Iterations。
7. 必要的控制安全机制。
8. 异常状态诊断和隔离机制。

但必须满足以下要求。

### 6.1 不改变核心 Action Mapping

保留：

\[
q_{\mathrm{target}}
=
q_{\mathrm{mid}}+\alpha a_t
\]

如果诊断证明过大的目标阶跃导致控制不稳定，可单独增加可配置的 PD Target Slew-rate Limiter。

其作用应是限制目标在相邻控制周期内的变化速度，而不是永久缩小关节活动范围。

如果采用这一方案，必须展示：

- 原始 Action Mapping 仍可覆盖整个关节范围。
- 实际下发的滤波目标及其状态。
- 控制滤波是否在训练、Evaluation、Replay 与 WM 想象过程中一致。
- 是否需要为滤波器增加状态观测，避免出现隐藏的控制器内部状态。

不允许通过悄悄裁剪动作或修改 Reward 来伪造稳定性改善。

### 6.2 不通过隐藏错误实现“修复”

禁止：

- 删除异常检查。
- 任意提高异常速度阈值。
- 将异常关节位置强行裁剪回限位。
- 把异常转移写入 Replay Buffer。
- 仅靠捕获 `FloatingPointError` 就宣称问题解决。

可以改善异常环境的单独 Reset 与训练恢复，但必须保留异常计数和证据，并确保已污染的状态不会进入 Replay、WM 或 BPTT。

## 7. 第六阶段：验证修复效果

首先进行独立 Newton 测试，再恢复训练。

### 7.1 物理稳定性回归

要求：

- 单环境、多环境均可运行。
- 真实关节位置、速度无明显非物理跳变。
- 不再出现类似 -13 rad、-2378 rad/s 的异常。
- 不出现未解释的大幅关节限位穿透。
- 无 NaN/Inf。
- 无异常约束容量 Overflow。
- PD Target、实际力矩和关节状态可正常记录。
- 修复不会明显破坏正常关节控制响应。

应通过实际测试数据确定合理的越界容差和速度报警阈值，不要把它们当作求解器硬限位。

### 7.2 固定动作对照

使用相同初态和相同动作序列，对比：

**Baseline：原 M4.1 配置**

**Fixed：修复后配置**

记录：

- 异常数量。
- 最大关节限位越界。
- 最大关节速度。
- Root Linear / Angular Velocity。
- Torque Saturation Ratio。
- Contact / Solver 状态。
- Simulation FPS。

优先证明修复对已发现的异常有效，而不是仅观察一次新的随机 Rollout 没有出错。

### 7.3 长时间训练稳定性

在物理回归测试通过后，进行短期训练验证。

建议在本地 RTX 4060 8GB 上，使用原 M4.1 环境数量或经过实际显存测试的保守环境数量。

先执行约 100–300 iterations 的训练 Smoke Test。

随后进行至少与历史失效规模可比较的稳定性验证，优先覆盖不少于约 76 万条真实转移。

如果预算允许，可继续完成不少于 1500 iterations 的修复后训练测试。

记录：

- Physics Exception Count。
- Invalid Transition Count。
- Joint Limit Violation。
- Max Joint Velocity。
- Torque Saturation Ratio。
- WM Loss。
- Actor / Critic Loss。
- Episode Length。
- Survival Rate。
- Foot Tracking RMSE。
- Training FPS。
- GPU Memory。

不要仅以异常消失作为训练成功的唯一标准，还应确认 Policy 的学习链路正常、指标没有明显退化。

如果修改了影响模型语义或训练状态兼容性的参数，请从头训练；若只是数值求解器参数修改，也要检查恢复 Checkpoint 的状态、Replay 和归一化器是否兼容。
