# M4.5 — Upper-body Motion Prior Ablation

## 一、任务目标

当前项目为 Roban 21-DoF 人形机器人，基于 SuperMimic 范式的 World Model + BPTT + Asymmetric Actor–Critic，在 Isaac Lab 3.0 + Newton/MJWarp 中实现 F2 Footstep Tracking。

M4.3 已成功完成 F2 的四次计划落脚，但 Reference 与闭环 Policy 的并排视频表明，上半身姿态和手臂运动仍不够自然。

M4.4 取消 PD Target Hard Clamp 后，Footstep Tracking 和实际力矩饱和等指标退化，因此本轮明确恢复 M4.3 的 Hard Clamp。

**M4.5 的唯一主要实验变量是增加弱 Upper-body Motion Prior Reward。**

本轮目标：

1. 保持 F2 完整四次落脚的能力。
2. 改善手臂和腰部相对 F2 的运动跟踪。
3. 减少不自然的上半身姿态和动作。
4. 分析 Upper-body Prior 与 Footstep Reward 的梯度关系。
5. 确保新先验没有破坏 WM/BPTT 的训练稳定性。
6. 完成 5000 iterations 正式训练及统一独立评估，与 M4.3 做对照。

请实际检查代码、实现修改、运行测试、完成训练和结果分析，不要只生成计划。

## 四、任务二：激活 Upper-body Motion Prior

当前 M4.3 已经实现 `body_prior`，但其 Reward Weight 为零。

请检查 `supermimic/roban_task.py` 中该奖励的实际实现。

原设计大致为：

\[
r*{\mathrm{body}}
=
Q\left[
0.7\exp\left(-\frac{\mathrm{MSE}(q*{\mathrm{arm}},q\_{\mathrm{arm}}^\*)}{0.5^2}\right)

- 0.3\exp\left(-\frac{\mathrm{MSE}(q*{\mathrm{waist}},q*{\mathrm{waist}}^\*)}{0.5^2}\right)
  \right]
  \]

其中：

- \(q\_{\mathrm{arm}}\)：实际手臂关节角度。
- \(q\_{\mathrm{arm}}^\*\)：F2 手臂参考角度。
- \(q\_{\mathrm{waist}}\)：实际腰部关节角度。
- \(q\_{\mathrm{waist}}^\*\)：F2 腰部参考角度。
- \(Q\)：已有的质量门控。

### 4.1 初始方案

优先复用现有 `body_prior`，暂定：

\[
\boxed{w\_{\mathrm{body_prior}}=0.10}
\]

这是待验证的实验值，不应预设它是最优权重。

其余 Reward 权重保持 M4.3 原样。

请核查完整公式、归一化方式及质量门控，并说明它们与上述表达是否一致。

### 4.2 检查质量门控

重点检查：

- `quality` 如何计算。
- 是否依赖 Root Height、Orientation 或其他跟踪误差。
- 在当前 M4.3 Rollout 中，`quality` 的 Mean/P10/P90。
- 是否在机器人偏离参考时趋于零。
- 是否导致 Body Prior 丧失恢复梯度。
- 是否在正常步态阶段持续有效。

如果发现 `quality` 存在明显问题，请先报告诊断，不要私自删除门控或同时重构公式。

### 4.3 防止 Privileged Information Leakage

保持当前 Asymmetric Actor–Critic：

Actor 只能接收原有 Proprio History 和 Foot/Root Goals。

Critic 可以继续接收完整未来 F2 Reference。

Body Prior 的目标可以用于 Reward 计算，但不能未经设计直接加入 Actor 观测。

需要检查 Actor 输入维度及归一化器，确认未产生意外的信息泄漏。

## 五、任务三：Reward 数值与梯度验证

正式训练之前，使用 M4.3 冻结 Actor 和真实 Newton Rollout 验证 Body Prior。

分别统计：

- Body Prior Reward。
- Arm Tracking Error。
- Waist Tracking Error。
- Body Prior Quality Gate。
- 各项梯度范数。
- Body Prior 在总 Actor Loss 梯度中的相对贡献。

### 5.1 梯度检查

计算：

\[
g*{\mathrm{foot}}
=
\nabla*\theta J\_{\mathrm{foot}}
\]

\[
g*{\mathrm{body}}
=
\nabla*\theta J\_{\mathrm{body}}
\]

统计：

- Foot Gradient Norm。
- Body Prior Gradient Norm。
- Gradient Cosine Similarity。
- 两者合成梯度范数。
- 上半身输出通道与下肢输出通道的动作梯度。

尤其检查：

\[
\cos(g*{\mathrm{foot}},g*{\mathrm{body}})
\]

是否长期为负。

对于共享 Actor 参数和输出动作通道，请分别报告对应梯度的定义及其作用，避免混淆参数梯度和动作梯度。

### 5.2 确保 Body Prior 不只是增加回报

验证：

1. 当 Arm Joint Error 较大时，Body Prior 是否仍有有效梯度。
2. 当 Arm Joint Error 减小时，Reward 是否上升。
3. 是否存在长期接近零的质量门控。
4. 是否在 BPTT 中产生 NaN、Inf 或异常梯度。
5. Newton 与 WM Reward 实现是否一致。
6. 是否与其他奖励发生明显的数量级失衡。

如果 `0.10` 权重造成明显数值问题，先诊断并报告，不要未经记录直接更换正式实验参数。

- Body Prior 局部奖励梯度与 Newton 有限差分的方向一致率。
- Foot Reward 局部梯度方向一致率。
- Body Prior 与 Foot Reward 的 BPTT 梯度余弦。
- Critic Bootstrap 与 Body Prior 梯度余弦。

对于新 Body Prior 的梯度，使用同一组 Newton 状态、同一位置目标、同一奖励函数进行配对比较。

不要将不同策略采集的数据集上的预测误差直接解释成模型优劣。

如果 M4.5 上半身改善但 Footstep Tracking 退化，需要分析是否与梯度冲突有关。
